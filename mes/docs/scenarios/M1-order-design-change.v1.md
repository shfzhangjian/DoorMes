## S — 业务场景

已有设计供订单选择，精确版本与逐件 BOM 同时冻结；定制订单经销售提交、研发领用绘图并明确绑定。后续变更需申请、独立审核、生产采用三个步骤，旧版始终可查。

不是正式下料场景：当前模拟目录仅提供参考参数，`productionReady=false`，本测试不下发生产或采购指令。

## A — 断言

- ASSERT-01：HTTP 返回值、SQL order/version 行与 JSON SHA 一致；保存回读而非内存占位。
- ASSERT-02：内部组成件 ID 唯一且修改尺寸后稳定；型号/短编号不代替内部 ID。
- ASSERT-03：文档数量和订单套数不重复放大；四边框不是一行“型材系统”。
- ASSERT-04：申请/批准/执行状态分离；无权限审核、未批准执行、重复采用、旧订单版本写入应被拒绝。
- ASSERT-05：需求中心不能直接修改/提交/领用已关联订单的需求，避免双入口失同步。
- ASSERT-06：readonly 图纸即便正好是图纸当前版也不能保存；历史不能覆盖头版本。
- ASSERT-07：颜色、规格、选型版本变化可见；参考/包络参数均不宣称正式加工尺寸。
- ASSERT-08：实际窄屏横溢出可滚，宽屏无横溢出不产生多余滚动条；主体底边紧邻分页。
