# 图形、BOM与工艺架构

文档版本：0.5.14  
状态：已确认的迁移设计

## 1. 核心约束

SVG、Canvas和Three.js对象只负责显示及命中测试。BOM与工艺只能读取设计领域模型、拓扑关系和制造特征，禁止扫描显示节点进行算料。

所有端统一使用下列链路：

```text
用户命令
  → Design Graph
  → Geometry / Topology Resolver
  → Manufacturing Feature Extractor
  → Rule Engine
  → EBOM / MBOM / 下料 / 工艺路线 / 生产实例
```

设计修改与预览仿真必须是两条不同状态链。设计命令修改可持久化对象并触发BOM失效；开度滑块、播放、当前选择和每扇即时进度只修改临时预览状态：

```text
设计命令 → Design Graph → Manufacturing Feature → BOM/工艺

预览意图 → Opening Preview Store → Kinematics Resolver
                                   → Pose Snapshot → SVG/Three.js/轨迹/碰撞预览
```

两条链只共享稳定对象ID和静态机构定义。预览状态不得增加设计revision、进入设计撤销栈或改变BOM哈希；需要持久化的“配置开启幅度”仍属于设计，当前动画进度不属于设计。

## 2. 映射关系

图形与物料不是简单的一对一：

| 设计语义 | 映射示例 |
| --- | --- |
| 一个设计对象到多个物料 | 一个窗扇产生扇型材、玻璃、压线、胶条和五金 |
| 多个对象到一个物料或工艺 | 两根型材形成一个连接节点及一组紧固件 |
| 可见对象不产生物料 | 标注、选框、辅助线、室内外标签 |
| 不可见对象产生物料或工艺 | 螺钉、密封胶、钻孔、端铣、排水槽 |

每条BOM或工艺结果必须记录：

- `sourceObjectIds`
- `sourceFeatureIds`
- `ruleId`和`ruleVersion`
- 公式标识、输入和输出
- 物料目录快照ID
- 计算批次ID

### 2.1 分层身份、加工编号与产品谱系

型号、物资编码、设计对象、装配位置和实物生产编号回答的是不同问题，禁止复用一个字符串兼任。所有进入切割、钻铣、组角、装配、质检、包装或备件替换的加工对象都必须能获得生产身份；螺钉、胶条等是否逐件、成套或按批追踪，由目录中的追踪粒度决定，不能为了“都有号”而给每颗通用紧固件虚构无业务价值的序列号。

| 层级 | 回答的问题 | 约束与示例 |
| --- | --- | --- |
| 窗业务编号 `WindowUnit.mark` | 设计图、工厂图和业务沟通用什么短号引用整樘窗 | 设计内唯一、可人工修改，如`C2`或`W-01-02`；只用于索引，不承载产品名、型号或逐件生产号 |
| 目录身份 `catalogItemId + catalogVersion` | 采用哪条已审核目录定义 | 不可变快照，如 `profile.al70.sash@3.2.0` |
| 业务型号 `modelCode` | 设计/采购人员选的是什么型号 | 与实物编号分开，如 `AL70-S01`、`HW-TT-STD` |
| 物资编码 `materialCode` | ERP/仓储按什么物资备料 | 同一编码可对应多件实物，不得当序列号 |
| 设计对象ID `sourceObjectIds` | 来源是哪樘窗、哪扇、哪根梃或哪个连接件 | 内部稳定技术身份，如 `WIN-001:cell.1.1.panel.P1` |
| 制造特征ID `sourceFeatureId` | 哪条版本化算料/工艺规则产生了工作件 | 如 `WIN-001:feature:...sash.top` |
| 装配位置 `assemblyPath + positionCode` | 该件位于哪个组合/窗/框扇/边位 | 结构化父子链，如 `A01/U01/S1/PROFILE-TOP` |
| 实物身份 `productionInstanceId` | 数据库中不可变地指向哪件实物或哪批料 | 使用无业务语义的内部唯一ID，不随改号或移位改变 |
| 生产编号 `productionNumber` / `lotNumber` | 工人、标签、扫码和备件业务如何识别它 | 正式签发后唯一且不可重用；批料使用独立批号 |

`productionNumber`可以由人工输入，也可以由版本化编号规则自动产生，但两条路径必须经过同一个标准化、查重和占号接口。设计阶段只生成可重复计算的`planned`编号；正式制造包发布时才调用企业级编号提供者完成`reserve → issue`。本地离线算法只能保证当前设计/制造包范围不重复，不能宣称跨电脑、跨订单或跨工厂全局唯一。

窗业务编号与生产编号的生命周期不同：设计人员可在窗体属性中修改前者，2D和工厂图只用它做短引用；后者针对具体型材、玻璃、五金套、连接件或批料，由制造计算/签发流程生成。产品模板名称、业务型号和物资编码必须显示在各自字段或表列，禁止再次拼接到窗业务编号中。

编号可以包含可读的组合层次片段，例如`ZCS-260922-O0123-A01-U01-S1-PF-T-0007`，但层次关系仍必须另外保存为结构化`assemblyPath`和父子装配ID。返修换件、拆装或改挂位置时，不改写已经签发的实物身份；通过`replacementOf`、`installedAt`和谱系事件记录变化，避免“位置一变，历史扫码全部失效”。

组合节点本身也属于可追踪对象：`FabricationAssembly → WindowUnit → Frame/Sash/JointAssembly → Workpiece`分别拥有装配身份，叶子工作件再关联型号、物资和实物编号。备件以原件生产号、型号/版本、适配装配路径和替代关系查询，不能仅凭显示名称或当前BOM数量推断。

编号服务使用面向未来HTTP/ERP/MES接入的异步端口，绘图/BOM核心只依赖契约：

```text
ProductionNumberProvider
  preview(context, policyVersion)        -> 候选编号（不占号）
  validateManual(number, context)         -> 格式、范围和可用性
  reserve(request, idempotencyKey)        -> 原子占号/防重复
  issue(reservationId, releaseRevision)   -> 正式签发并冻结
  release(reservationId, reason)          -> 仅释放未签发占号

ProductionIdentityContext
  organization/site/order/release
  catalogItem/model/material
  assemblyPath/positionCode
  sourceObject/sourceFeature/trackingMode/sequence
```

编号规则必须保存`policyId + policyVersion + inputSnapshot`。人工编号同时保存`source=manual`和原始输入；系统编号保存`source=generated`。正式编号冲突、服务不可达或目录未声明追踪粒度时阻断生产发布，但不阻断2D/3D设计和预览BOM。

实施分三段：

1. **现在、扩展推拉等新构件之前**：冻结上述契约，给现有计划实例补齐型号快照、结构化装配路径、位置号、内部实例ID和可替换编号策略；继续使用本地确定性提供者，只标记`planned`。
2. **BOM确认/工厂制造包阶段**：接入可配置规则、人工编号校验、集中查重/占号/正式签发、标签载荷和不可变发行快照；此时才承诺企业范围唯一。
3. **生产执行与售后阶段**：接入扫码、供应商批次、工序、质检、包装、返修、拆换和备件谱系；账号权限与审批仍按既定计划后置，不污染当前绘图功能。

当前0.10.81已经完成第一段：`ProductionMaterialInstance`保存独立`productionInstanceId`、目录/型号快照、物资编码、结构化装配路径、位置号、件/套/批追踪粒度和编号策略证据；路径中的组合、窗、框扇/连接装配与工作件节点也各有稳定计划身份。计算器接受可替换的同步计划编号策略，默认规则生成包含层次提示的`PLN:`号码，并在返回前拒绝空号、重复实例ID和重复计划号。异步`ProductionNumberProvider`只冻结端口，尚未冒充已经接通的集中签发服务。

### 2.2 型材安装截面快照

材料目录中的系列/型材版本提供截面默认值，设计对象必须保存一次完整快照，而不能只保存会随目录升级漂移的预设名称。首批快照包含框深、扇深、玻璃深、扇相对外框正面的搭接退距、五金突出量、飞梃深度及飞梃前向突出量；框/扇正视面宽继续由窗体型材几何保存。

新建窗可从内置参考预设或材料目录复制快照；用户自定义时通过单个领域命令整体替换并进入同一撤销步骤。几何层负责统一校验和解析，SVG俯视、Three.js场景、制造特征和后续BOM规则只读取该快照，不得各自设置“看起来合适”的深度常量。目录版本、快照值和修改来源必须一起进入审计记录，使历史设计在目录升级后仍能按当时尺寸重现。

### 2.2.1 连接件业务型号快照

设计用户选择的是连接件业务型号，不直接维护`jointType`、成品宽度或制造规则ID。每次选择必须把目录项ID/版本、业务名称/规格、物理连接类型、成品宽度、允许及默认工厂范围、精确制造规则ID/版本和目录审核状态一起冻结到`EngineeringJoint.catalogSelection`。几何实体上的类型、宽度和范围是该快照的可验证物理投影，不能与快照相互矛盾。

保存恢复、撤销重做、2D/3D对象追溯、工厂表和EBOM必须消费同一快照；计算器按`manufacturingRuleId@version`精确解析，不得仅按连接类型读取“当前最新”规则。旧项目没有快照时继续按历史类型/宽度兼容计算，只有在用户明确应用型号后才补写快照。内置记录标记为参考目录，未来企业正式目录沿用同一契约并将审核状态提升为工厂批准，不需要重写几何、渲染或BOM链。

### 2.3 安装宿主与包边物料分层

`WindowInstallation`同时描述现场宿主和可采购包边，但两者必须分层：墙厚、墙材、窗台高与框位只用于安装空间、2D/3D剖面和碰撞诊断，不生成产品物料；`surround.enabled=true`且被应用边选中的外包套、内包套、衬板、连接件和密封才产生安装制造特征。

几何层统一解析规范应用边、各边长度、相邻转角数、周长、衬板面积和启用层。Three.js使用该结果生成`installation.surround.{layer}.{side}`构件，计算引擎以相同来源ID生成`InstallationMaterialFeature`、EBOM、MBOM、切长、采购汇总和计划生产号。禁止扫描Three Mesh算料，也禁止BOM重新解释一套应用边规则。

现场墙体组不得拥有伪造的产品对象ID，且必须标记排除BOM；包边构件当前回链所属窗ID，待安装对象树建立后再提升为独立设计对象。显示层的墙体/包套显隐不得修改Installation、撤销栈或计算结果。

墙体、窗台下墙、外包套、内包套和衬板还必须由几何层输出统一的毫米障碍体；Three只把这些体积换算为Mesh，运动诊断直接读取毫米体积，禁止扫描Mesh或按屏幕包围框判断。诊断将窗扇配置截面作为真实旋转盒，沿共享机构的完整能力路径采样，并以15轴分离轴算法判断实际相交，不能用整个运动AABB代替，否则会把圆弧包络内但窗扇从未经过的空间误报为冲突。

安装空间冲突属于生产确认阻断，不属于BOM物料：结果必须记录窗ID、面板ID、运动模式、首撞进度、实际角度、穿透量和`installation.wall.*`或`installation.surround.*`目标ID。当前180区间采样和0.1mm穿透阈值用于参考设计确认；供应商最小间隙、公差和法规净空将由版本化安装规则膨胀障碍体或增加独立安全间隙，而不是误用浮点穿透阈值或把规则写进渲染器。

#### 2.3.1 真实墙体、洞口与窗体的权威边界

正式业务中的墙体是门店/安装项目独立绘制、测量或导入的环境对象，绝不由`WindowUnit`反向计算并保存。`WindowUnit`只描述可制造门窗及其交付安装接口；现有`WindowInstallation`是单窗阶段的兼容安装接口和参考碰撞包络，不是建筑墙体实体。

未来对象关系固定为：

```text
StoreProjectDocument
  └─ WallAssembly（墙路径/平面、坐标、方向、高度、厚度、分层与环境材质）
       └─ WallOpening（名义/实测洞口、局部位置、宽高、窗台高、公差）
            └─ ProductPlacement（引用WindowUnit/FactoryProduct版本、安装变换、间隙和锚固方案）

WindowUnit / FabricationAssembly
  └─ DeliveryInstallationInterface（建议洞口、安装间隙、框位、包边与随货安装套件）
```

墙体来源可以是2D墙线拉伸、参数化墙面、现场测量或BIM/模型导入；无论来源如何，统一归一化为墙局部坐标系、厚度/高度和开洞集合。一个墙体可以拥有多个洞口，每个洞口可以安装一樘独立窗或一个工厂组合产品；两樘窗出现在同一画布不代表它们属于同一墙体。

工厂模式允许生成`ReferenceHostPreview`：依据窗外廓、建议间隙、墙厚、窗台高和可配置外延尺寸，临时画一面参考墙以检查剖面、开启与包边。该预览不得保存成真实`WallAssembly`、不得进入墙体工程量/BOM，也不得因为增加第二樘窗而自动宣称两窗同墙。当前3D“参考墙体”即此语义。

参考墙体按`InstallationSubject`计算，而不是固定按单樘窗计算。安装主体只能是一个独立`WindowUnit`，或一个由物理`EngineeringJoint`连成的`FabricationAssembly`：

1. 以连接图的连通分量确定安装主体；没有连接的相邻窗始终是多个主体，不能合并参考墙。
2. 将主体内N个`WindowUnitInstance`按各自刚体变换投影到组合局部坐标，求门窗实体外轮廓的几何并集，不能只按实例数量或屏幕包围框估算。
3. 删除连接处的内部共享边；拼樘料、加强料、连接片和内部密封属于`EngineeringJoint`，不得变成墙边、洞口边或包边应用边。
4. 仅对组合外轮廓按上/下/左/右版本化安装间隙做外偏移，生成一个建议洞口；参考墙再围绕这个整体洞口生成。
5. 包边默认沿组合外周连续计算；只有业务明确选择“分樘独立收口”时才按子窗外周生成，并必须记录接缝和重复材料处理规则。
6. 连接、断开、移动或修改任一子窗尺寸时，重算组合外轮廓、建议洞口、参考墙、包边、开启碰撞和安装校核；参考墙本身仍不进入BOM。

同一平面内的左右/上下拼接生成一面参考墙和一个整体洞口。转角窗或飘窗仍是一个安装主体，但其外轮廓跨越多个平面，应生成`ReferenceHostSurfaceSet`，不能把转角强行压成一面平墙。

尺寸关系禁止双向静默回写：

- 已测洞口约束产品放置；不适配时产生校核失败或工程变更请求，不能拉伸已发布窗体。
- 产品尺寸可以计算“建议洞口=产品外廓+版本化安装间隙”，但结果是建议/校核值，不能覆盖实测洞口或墙体。
- 墙厚、墙材、环境光照和相机变化只使门店场景重绘，不使窗本体BOM过期。
- 产品尺寸、包边或随货安装套件变化按影响标签使产品配置、安装校核或安装BOM过期，但不能改墙路径。
- 同墙多洞口、转角墙及复杂施工碰撞由`StoreProjectDocument`/后续Site模型负责；`FabricationAssembly`只表达工厂有物理连接的产品组合。

### 2.4 外观快照与构件模型资产

外观必须与物资、构件型号和渲染文件分层：`materialCode`是采购/生产身份，`appearancePresetId`是版本化表面快照，`componentModelId`是锁具等物理型号，`assetId`只定位纹理或3D文件。任一层都不得用另一层的字符串临时代替。

墙体、框、扇、中梃/飞梃、玻璃、包边和五金均可保存外观快照。框/扇等有方向的构件至少区分室外面、室内面和侧边；快照保存基础色、材质族、金属度、粗糙度、透明度、纹理集、UV比例、表面处理代码和版本。Three通过共享解析器和缓存生成PBR材质，SVG使用同一快照的基础色/透明度/纹理符号降级；任何渲染器不得再维护独立颜色表。

锁具等五金型号除外观外还要保存真实毫米尺寸、参数化或GLB形状、安装枢轴、安装轴向、LOD资源、2D降级符号、适用构件和版本。几何模型继续挂载于规范`mountOwnerPanelId`和连接锚点；更换外形不能改变运动公式，若型号改变物资、孔槽或安装位置，则必须通过目录规则改变物资编码/加工模板并使BOM失效。

用户自定义模型必须经过单位、方向、包围盒、三角面数、纹理、安全和内容哈希校验，再明确设置安装面、枢轴和实际尺寸。未发布资产只有预览资格，不得自动进入可生产状态。移动端可以选择低模LOD或参数化fallback，但业务尺寸、锚点、碰撞和BOM必须与PC相同。详细方案见`appearance-and-component-assets.md`。

### 2.5 共享模型的三种投影与职责边界

2D工程设计、3D真实仿真和工厂/安装技术图纸不是三套产品模型，而是同一设计图、几何快照、外观/型号快照和制造映射的三种只读投影：

| 投影 | 主要目的 | 必须表达 | 不作为权威依据 |
| --- | --- | --- | --- |
| 2D工程设计投影 | 屏幕上的绘制、选中、编辑和尺寸约束 | 几何、拓扑、构件关系、传统开启图示、内外径/格区/总尺寸、俯视开启、稳定对象ID | PBR纹理、灯光效果和照片级颜色 |
| 3D真实仿真投影 | 直观验证成品外观、开合运动、装配和安装空间 | PBR材质、纹理、玻璃、真实/参数化五金模型、开合姿态、装配位置、参考墙/洞口、碰撞与运动包络；尺寸和角度可按需覆盖显示 | 结构强度、抗风压、热工、隔声、水密/气密等专业计算结论 |
| 工厂/安装技术图纸投影 | 审核、归档、打印及指导加工、组装和安装 | 纸空间线宽、标注、符号、剖面/节点、材料与构件编码、BOM/明细表、标题栏和版本 | 屏幕缩放后的像素位置、真实纹理和渲染颜色 |

三种投影必须使用相同毫米几何、对象ID、材料/型号版本和开启机构。不得在SVG、Three.js或打印导出器内重新计算内外径、连接宽度、洞口或BOM；投影之间的差异只允许是表达规则、可见层和纸面布局。

#### 2.5.1 语义标注与纸空间布局

正式出图必须建立独立的`DrawingSheet`、`DrawingView`和`DrawingAnnotation`语义层。标注保存所引用的对象ID、几何端点、标注类型、视图、图层、优先级和样式；布局器再根据图幅、比例和纸面毫米间距安排尺寸通道。禁止扫描最终SVG文字或Three覆盖层反推工程图。

首个实现位于`@doormes/drawing-model`：它不依赖DOM、SVG或Three，负责A4/A3物理图幅、技术视图、语义标注、不可变快照及纸面尺寸通道。现有交互SVG已经复用相同的重叠通道分配规则，但仍保留屏幕交互间距。`@doormes/drawing-projection`只从共享设计与几何生成工厂图语义快照，`@doormes/renderer-drawing-svg`再将快照序列化为物理毫米黑白SVG；两者均禁止读取交互SVG、相机或屏幕缩放。

尺寸排布采用“局部/明细尺寸靠近图形，分段尺寸居中，总体尺寸最外层”的稳定顺序；同一视图只保留一组明确的室内/室外方向基准，开启方向使用行业图示。关闭立面以传统开启符号表达类型，实际运动角度和弧线放在俯视/剖面或3D仿真覆盖层，避免将全部派生尺寸同时堆叠到一张图上。

用户补充说明必须使用独立`DrawingTextLabel`，不能伪装成尺寸或由渲染器临时拼接。标签只保存所属窗/组合根、自由毫米位置、适用立视/俯视、纸面字号、颜色、旋转、对齐和显式打印继承意图；选择、移动、编辑、删除、撤销和项目恢复都使用稳定对象ID。安装方式、模板名、参考墙参数等系统字段不得自动生成标签；正式工厂图或安装图只有在对应出图配置明确接受`printVisible`标签时才可投影，并仍需由纸空间布局器避让，不能直接复制屏幕像素位置。

工厂图与安装图使用不同出图配置：工厂图重点是产品总装、分格、构件/材料编码、加工节点、BOM和工艺引用；安装图重点是墙体/洞口、框位、间隙、锚固、密封、包边、室内外和现场节点。两者都必须在黑白打印时可读。

#### 2.5.2 设计选型、正式MBOM与图纸表格边界

图纸上的“设计选型”只证明当前设计引用了哪个型材系统、玻璃、五金系统或包边业务型号，不自动等同采购/下单数量。正式MBOM必须来自计算引擎的`FormalBomResult`，图纸投影只能筛选、分组和排版已有物料行，禁止根据2D填充颜色、3D材质、GLB外形或选型标签重新推测物料。

`DrawingTable`保存表格类型、物理纸面位置、列、行、严重级别及逐行来源ID。当前工厂总装图按已确认界面只保留“门窗设计组成件”表：未加载同revision计算结果时仅列选型摘要；加载结果后按逐件生产身份展开框料、扇料、挺、压条、玻璃、胶条、五金、包边和连接件，并显示物料编码、设计下料长/端角、玻璃长宽厚、数量和用户备注。可见加工件的逐件编号通过共享几何锚点回标立面；胶条、密封与隐藏安装耗材只进入表格，不虚构图面位置。未经供应商/工厂审核的毛坯余量不得打印为正式尺寸；锯缝、端部余量和定尺排料属于后续下料清单。生产状态与工序不混入该表；完整MBOM、路线和诊断属于后续制造包页面。单页装不下时生成同图号/版本/revision的组成件续表页，预览、SVG和打印/PDF共享冻结页集及第N/M页信息，禁止静默截断或只留下“另有N行”。

正式计算结果进入图纸时必须同时携带来源设计revision。只有来源revision与`DrawingSheet.sourceRevision`完全相同才允许打印“正式MBOM”；缺少企业目录或计算快照时，图纸保留设计选型并标记“仅供设计核对、禁止作为下单MBOM”；快照过期时不打印旧物料，而是输出阻断诊断。这个边界使未来正式目录接入、页面预览、SVG/PDF适配和多页明细均复用同一图纸模型，不需要把参考目录硬编码进导出器。

#### 2.5.3 材质与仿真边界

3D使用完整外观快照进行真实材质仿真；2D设计视图只做可辨识的颜色/填充降级；正式技术图纸以`materialCode`、规格、表面处理代码、构件型号、标准填充和材料表作为权威身份。允许附加彩色效果页或3D快照帮助沟通，但颜色和纹理不得替代物资编码、版本及文字说明。

当前3D“仿真”范围是视觉、运动学、装配位置、安装空间和碰撞仿真。结构有限元、抗风压、热工、隔声、水密/气密等结论必须由未来独立的版本化计算模块、材料性能目录和规范规则产生；未接入这些模块前，界面和交付物不得暗示已经完成相应专业校核。

#### 2.5.4 选择对象到装配/零件制造图包

后续`SHEET-005`允许用户从2D、3D或对象树选择任意稳定业务对象并生成对应图包，但“选择”只提供对象ID，不能直接决定物料或工艺。`DrawingScopeResolver`必须先根据设计父子关系、装配关系、制造特征来源和正式计算快照，把选择解析为明确的`DrawingManufacturingScope`：

- 选择整窗或制造组合时，作用域包含其可制造后代、内部连接及正式装配层级；
- 选择窗扇、框/梃、玻璃、五金、连接件或包边时，作用域默认只包含该对象、它拥有的制造特征以及读图必需的配合接口，不把整个产品物料全部带入；
- 同一物理件由多个画面图元表现时仍只按稳定业务/制造ID计一次；选择渲染网格、颜色或纹理不能产生BOM行；
- 对接口类对象（合页连接、锁点/锁座、拼樘连接等），图纸可引用配合端作为虚线/基准，但必须区分“本图供货件”和“配合参考件”。

输出包至少包含适用的正投影、俯视、剖面/节点或爆炸关系、装配方向与基准、关键尺寸/公差、材料编码和型号版本、作用域EBOM/MBOM、下料/孔槽/安装参数、工艺模板、逐件生产号，以及显式分类的随货备件、维护备件和易损件。备件不能通过给正式MBOM数量任意加一实现，必须来自版本化备件规则并保留与主件/型号的适用关系。

图包与总装图使用相同revision门禁。设计revision、正式计算快照、目录/工艺模板或备件规则任何一项过期/缺失时，只能输出带诊断的设计核对版，禁止标记为可下发制造包。

## 3. 制造特征

首批标准制造特征：

- `CutFeature`
- `EndMillFeature`
- `HoleFeature`
- `NotchFeature`
- `DrainageFeature`
- `SealPathFeature`
- `HardwareMountFeature`
- `JointFeature`
- `SurfaceFinishFeature`

构件组合先产生拓扑和制造特征，再由版本化规则生成物料、下料和工艺。界面事件不得直接追加BOM行。

`EngineeringJoint`的制造映射以连接对象而不是参考墙或相邻窗框为所有者。计算引擎先从共享组合几何取得连接长边与间隙，再由`EngineeringJointManufacturingRule`解析连接型材、可选加强衬料、紧固件最大间距/最少数量、连续密封倍率、盖缝料及钻孔/组装模板。材料角色生成`EngineeringJointMaterialFeature`并进入MBOM、采购汇总、下料和计划生产号；钻孔/组装生成`EngineeringJointProcessFeature`，只引用材料特征而不重复计料。普通拼樘、加强拼樘和上下叠接当前使用版本化内置预设；未来工厂目录可整体替换。显式空目录或不完整工艺模板必须产生定点阻断诊断，组合窗本身不再构成禁止生产确认的理由。

开启扇五金分为两层：`HardwareDemandFeature`只描述采购/领料数量，`HardwareMountFeature`描述扇侧与框侧安装关系，`HardwareMachiningFeature`描述工作件需要的钻孔或开槽模板。安装和加工特征不得直接物化为MBOM行，以免同一套五金因扇侧、框侧各有安装点而重复计料。

合页叶片与锁点/锁座通过稳定 `connectionId` 配对。闭合坐标统一由 `geometry-topology` 以毫米解析；SVG画闭合立面，Three.js将扇侧成员挂到运动组、框侧成员留在固定组，工艺引擎读取同一坐标。目录未提供供应商 `machiningTemplateId` 时允许预览和BOM对照，但必须输出阻断诊断，禁止进入生产确认。

开启方向必须以真实铰接边而非界面习惯字段建模。侧铰平开使用 `hingeEdge: left/right` 并绕竖轴运动；上悬窗使用 `hingeEdge: top` 并绕顶部水平轴运动，`top_out/top_in`只决定窗扇底边沿室外/室内方向偏转。旧算法若包含无业务含义的侧边占位字段，只能由兼容适配器在调用旧引擎时构造，禁止回流到正式领域对象、渲染或工艺层。

双扇交汇边必须同时描述“连接来源”和“物理宿主”：`panelId`保留产生连接规则的面板，`mountTarget`区分窗扇、窗框、固定中梃或飞梃，`mountOwnerPanelId`只在运动宿主存在时指定3D父级。飞梃窗中，主动扇锁座、从动扇操作杆及天地插销随从动扇飞梃运动，天地插销锁座留在外框上/下框。固定中梃窗中，中梃归属外框，两扇均为独立扇，四个交汇锁座以固定中梃为工作件并保持静止。禁止用“对向扇侧边锁点”模拟任一结构；供应商孔槽和装配模板未录入时仍只允许预览与BOM审计。

正式工程的 `geometry-topology` 包是PC、移动、SVG、Three.js和计算引擎共同依赖的纯几何层。规则网格负责快速生成贯通横竖梃；拓扑成员负责单个区域内的局部梃、连续梃和T形连接。成员跨度使用宿主区域内0至1归一化坐标，制造长度统一在计算时换算为毫米。

局部梃分区使用闭合矩形验证：贯通分割及闭合T形分割可派生多个玻璃区域；悬空、未闭合的局部梃保持可见且保留型材算料，但玻璃暂不拆分，并产生待审计的几何状态。该行为当前为原型兼容结果，是否允许进入正式下单需在BOM确认规则中单独决定。

## 4. 算法迁移方式

1. 使用固定设计JSON和BOM结果固化现有算法行为。
2. 将原算法包装为 `LegacyBomCalculator`，保留兼容入口。
3. 定义类型化的 `BomCalculatorPort` 和规范化结果。
4. 实现制造特征提取器和规则跟踪信息。
5. 按外框、中梃、填充、开启扇、五金、节点、组合窗、安装包套逐组迁移。
6. 所有样本同时运行旧、新算法，比较数量、尺寸、编码、损耗及来源。
7. 已知错误作为审核差异处理，不为了通过旧测试而继续隐藏错误。
8. BOM确认和冻结产生不可变快照，后续设计变更只能创建新版本。

## 5. 多端一致性

桌面、平板和手机只提供不同输入适配与布局。它们提交相同命令，例如：

```text
SplitWindowGridCommand
RemoveLastWindowGridTrackCommand
MoveWindowGridDividerCommand
EqualizeWindowGridCommand
MergeWindowGridDividerCommand
Add/Move/RemoveWindowTopologyMemberCommand
SetOpeningTypeCommand
ConnectWindowsCommand
ChangeMaterialCommand
```

同一初始设计执行同一命令序列，最终设计JSON、制造特征、BOM和工艺结果必须完全相同。

允许PC与移动端拥有独立布局壳和交互控制器，但二者只能依赖共享应用命令。以下能力严禁进入端专用包：

- 领域对象和构件结构定义。
- 几何、拓扑和开合计算。
- SVG图形及Three.js场景的业务生成逻辑。
- BOM、下料和工艺规则。
- 数据格式、校验、版本迁移和冻结语义。

端专用包只允许包含布局编排、面板导航、手势识别、鼠标/键盘映射和临时界面状态。

开合运动采用独立纯函数内核：静态 `OpeningAssembly`与每扇预览进度共同解析为 `OpeningPoseSnapshot`。SVG立面、俯视轨迹、Three.js构件、随动五金及碰撞包络只消费姿态快照，不得各自实现机构公式。普通推拉、提升推拉、PSK、入墙、转角和折叠均在同一策略接口上扩展。
