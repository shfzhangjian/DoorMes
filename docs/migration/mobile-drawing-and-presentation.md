# 移动端绘制与展现迁移计划

文档版本：0.4.1  
状态：首版共享绘制/属性抽屉与2D触控导航已实现，继续迁移完整构件  
覆盖设备：桌面浏览器、横竖屏平板、横竖屏手机、触控笔设备

## 1. 目标与边界

移动端必须支持查看和实际绘制，不定位为只读预览器。桌面与移动端的领域数据、几何结果、2D/3D联动、BOM和工艺计算必须一致。

移动端允许并推荐使用独立布局壳。该布局壳是共享正式前端上的第二种交互编排，不是复制一套移动业务代码：

```text
                         Shared Design Application Core
                       /                                \
Desktop Layout Shell  /                                  \  Mobile Layout Shell
鼠标、键盘、三栏布局                                         触控、笔、抽屉与底栏
```

两个布局壳共享：

- 同一设计文档、领域对象和稳定ID。
- 同一构件目录、工具定义和属性定义元数据。
- 同一应用命令、撤销重做、校验和持久化。
- 同一SVG渲染器、Three.js场景构建器和对象映射。
- 同一几何、拓扑、开合、装配、BOM及工艺算法。

布局壳可以拥有自己的路由、面板开合、抽屉位置、当前手势和临时焦点状态；这些状态不能写入制造设计数据，也不能改变计算结果。

开合预览同样属于共享临时状态，而不是桌面或移动壳的私有业务数据。每扇当前开度、运动模式、选中集合和播放状态由共享 `OpeningPreviewStore` 管理；PC控制条与移动抽屉只发送相同预览意图。配置开度可以进入设计JSON，当前动画帧不得进入设计revision、撤销栈或BOM。

型材安装截面属于持久化设计数据而非布局状态。当前新建窗保存内置参考截面的完整尺寸快照；未来PC属性面板与移动属性抽屉只负责编辑同一份框深、扇深、玻璃深、搭接退距、五金突出量及飞梃截面数据，并提交同一个完整更新命令。SVG俯视和Three.js只能读取共享解析结果，移动壳不得设置另一组视觉常量。

移动端允许调整布局和输入方式，但不得：

- 删除桌面端已有设计能力。
- 建立独立的移动数据模型或移动BOM算法。
- 依赖悬停、右键或鼠标滚轮才能完成关键流程。
- 为提高性能而省略真实构件或改变制造尺寸。
- 在移动布局壳中复制构件定义、几何、SVG/3D生成、BOM或工艺算法。
- 在共享核心中通过设备类型分支改变领域规则。

首轮不强制实现离线PWA和原生App封装；二者作为正式Web移动体验稳定后的独立评估项。

## 2. 当前原型审计结论

原型已有有利基础：

- 页面包含移动视口声明。
- 部分2D拖拽、画布平移、自定义异形和3D拾取已使用Pointer Events。
- CSS已有两个响应式断点。

但尚不能视为移动端已经完成：

- 验收流程仍依赖鼠标悬停、左键、右键、滚轮和双击。
- 多处使用 `contextmenu`、`dblclick`、`mousemove` 和 `wheel`。
- 小屏布局主要把桌面三栏纵向堆叠，缺少以画布为中心的移动工作区。
- 未定义双指缩放、触控平移、长按菜单、误触阈值和触控笔规则。
- 未建立移动端自动化和真实设备验收矩阵。
- 3D没有明确的移动GPU质量分级和资源预算。

当前正式项目已完成的首批替代能力：

- PC侧栏与移动抽屉复用同一个构件属性编辑器和完整属性命令。
- 空白区单指平移、双指中心平移/捏合由纯触控状态机统一输出视图变化。
- 构件触控与画布导航隔离；550ms长按复用桌面右键的编辑/删除菜单。
- 390×844手机视口已做真实页面尺寸复测，底部面板与属性抽屉无横向溢出。
- 贯通/局部梃、三等分、均分及末轨删除使用与PC相同的工具定义、可用性判断和命令控制器。
- 工具、对象树和属性面板互斥展开，底部区域最多占55dvh并内部滚动，避免完全挤压画布。
- 选择窗体及其窗格、框或梃后，可从共享属性抽屉编辑总宽/总高，不依赖触摸设备难以发现的双击标注。
- 尚未完成移动工具库、所有原型构件、触控自动化矩阵及真实设备验收，因此整体状态仍为迁移中。

## 3. 移动端信息架构

PC与移动布局壳可根据设备能力或用户选择进入，但共享组件应优先复用。属性编辑器、工具元数据、对象树数据适配和BOM视图模型保持一致；壳只决定它们以侧栏、抽屉还是全屏页面呈现。

### 3.1 平板

- 画布始终为主区域。
- 工具库使用可收起侧栏或浮动抽屉。
- 对象树和属性面板使用右侧抽屉；横屏可固定显示一个面板。
- 2D、3D、BOM保持同级切换。
- 支持触控笔精确绘制和手指导航并存。

### 3.2 手机

- 画布使用全屏工作模式。
- 顶部保留项目、窗号、2D/3D和保存状态。
- 底部放置当前工具、撤销、重做、取消、完成和视图控制。
- 工具库、对象树、属性、BOM使用底部抽屉或独立全屏页。
- 数字尺寸使用专用数字输入面板，避免系统键盘遮挡目标构件。
- 复杂属性采用分组步骤，但提交的仍是与桌面端相同的命令。

## 4. 桌面与触控操作映射

| 桌面操作 | 移动端等价操作 | 设计要求 |
| --- | --- | --- |
| 左键选择 | 单击 | 选择与放置模式必须有明显区别 |
| 悬停预览 | 手指/笔按下拖动预览，或先选目标再确认 | 不能要求设备具有hover能力 |
| 右键菜单 | 长按或“更多”按钮 | 破坏性操作仍需明确确认 |
| 右键取消放置 | 固定可见的“取消”按钮、系统返回键适配 | 不把长按作为唯一取消方式 |
| 滚轮缩放 | 双指捏合；工具栏提供加减按钮 | 缩放中心跟随双指中心 |
| 中键拖动画布 | 双指平移；导航模式下单指平移 | 避免与构件拖动冲突 |
| 双击尺寸 | 双击或选中后点击尺寸编辑 | 提供可发现的属性入口 |
| Ctrl/Shift多选 | 长按进入多选或显式多选模式 | 当前模式必须持续可见 |
| 键盘快捷键 | 撤销/重做/删除/完成按钮 | 外接键盘仍保留快捷键 |

关键操作不能只有手势入口，必须同时提供可见控件。

## 5. 交互架构

```text
PointerEvent / KeyboardEvent
          ↓
Input Adapter
          ↓
Gesture Recognizer
          ↓
Interaction Controller
          ↓
Shared Application Command
          ↓
Design Graph
```

`Interaction Controller` 可以分为桌面和移动实现，但它只能把输入翻译成共享命令。禁止控制器直接修改Design Graph内部结构，或直接生成SVG、Mesh和BOM行。

### 5.1 输入适配器

- 统一处理 `mouse`、`touch`、`pen` 三种 `pointerType`。
- 使用Pointer Capture保证拖动离开图元后仍能完成或取消操作。
- 分离点击、拖动、长按、双指缩放与双指平移状态。
- 阈值按CSS像素和设备类型配置，不直接写入业务代码。
- 画布区域使用受控的 `touch-action`；页面其他区域保留原生滚动。

### 5.2 坐标体系

- 输入统一转换为屏幕坐标、视口坐标、设计毫米坐标三层。
- 控制柄保持可触达的屏幕尺寸，不随设计缩放无限缩小。
- 吸附容差以屏幕空间判断，落点再转换为设计毫米值。
- 2D和3D都返回稳定 `objectId`，不返回渲染节点作为业务标识。

## 6. 2D移动绘制任务

1. 把残留的鼠标专用监听迁移到统一输入适配器。
2. 实现单指选择/拖动、双指缩放/平移和触控笔精确绘制。
3. 为框、中梃、开启扇、格条、节点、包套和多窗组合提供触控命中区。
4. 将右键菜单功能映射到长按与显式“更多”入口。
5. 将双击尺寸编辑映射到选中后的属性入口。
6. 增加放置中的预览、吸附反馈、可见取消和误触恢复。
7. 保证撤销/重做涵盖完整手势，而不是记录每个移动采样点。
8. 验证异形、局部中梃、组合窗及工程节点在手机和平板上可完成。

## 7. 3D移动展现任务

1. 保留Three.js和同一场景构建器，不维护移动专用几何。
2. 区分轻触选择与拖动旋转，超过移动阈值后不得误触发选择。
3. 支持单指旋转、双指缩放和平移，并提供重置视角按钮。
4. 2D选中对象在3D中高亮，3D点选对象同步回2D与对象树。
5. 对移动设备限制渲染像素比，按能力关闭阴影或降低抗锯齿质量。
6. 使用按需渲染、几何与材质复用、资源释放和必要的层级细节策略。
7. 页面切到后台、切换设计或销毁弹窗时暂停动画并释放无用资源。
8. 性能降级只影响视觉质量，不得改变尺寸、构件数量和对象ID。
9. 提供可见的构件单选/多选、实际开启角度、选中/全部开关、播放/暂停入口，不能只依赖在3D画布上拖动；百分比只允许作为动画内部时间坐标。
10. 开度滑块拖动时暂停OrbitControls手势；释放后恢复视口交互，避免窗扇控制与相机旋转冲突。
11. 飞梃窗按主动/从动顺序开启并反序关闭；固定中梃两扇保持独立，规则与PC完全相同。

## 8. BOM与工艺联动

移动端编辑必须经过相同领域命令和失效传播机制：

```text
触控修改构件
  → DesignChangeSet
  → 标记受影响BOM为过期
  → 重算制造特征
  → 生成确定性BOM/工艺快照
```

移动端应能查看构件来源、规则版本和差异，但确认、冻结、反冻结等操作仍受统一权限控制，不能因为端类型改变权限规则。

## 9. 测试矩阵

### 9.1 自动化视口

至少覆盖：

- 390 × 844 手机竖屏。
- 844 × 390 手机横屏。
- 768 × 1024 平板竖屏。
- 1024 × 768 平板横屏。
- 1024 × 1366 大屏平板竖屏。
- 1366 × 768 桌面基线。

自动化使用真实触摸上下文验证主要流程，并同时覆盖Chromium与WebKit。视觉回归按设备布局分别保存基线，不要求手机与桌面像素排列一致。

### 9.2 功能一致性

对每个核心场景保存统一命令序列，分别在桌面和移动适配器执行，比较：

- 规范化设计JSON。
- 几何与拓扑结果。
- 对象ID和选择联动。
- EBOM、MBOM和下料结果。
- 制造特征及工艺路线。
- 撤销、重做和保存恢复结果。

另外增加“壳层边界测试”：构建检查禁止移动布局包反向依赖BOM、工艺和领域实现细节；移动端特有代码不得包含物料公式、构件几何生成或Three.js场景构造。

### 9.3 真实设备

发布前至少选择一台主流Android手机、一台iPhone、一台Android平板和一台iPad执行真实设备验收。具体最低机型和系统版本在M0基线阶段结合客户设备确定并登记，不能只依赖模拟器。

## 10. 首轮验收标准

- 核心绘制流程在手机和平板上不依赖鼠标专用操作。
- 所有关键按钮和控制柄具备足够触控区域，且无被安全区或键盘遮挡的问题。
- 同一场景的桌面与移动设计JSON、BOM和工艺结果完全一致。
- 2D/3D跨视图选中、显隐和开合联动一致。
- 旋转屏幕、浏览器缩放、前后台切换后不丢失未保存设计。
- 基准设备上的连续缩放、平移、构件拖动保持可操作；最终性能预算在M0实测后固化。
- 自动化回归、视觉回归和真实设备验收均通过。
