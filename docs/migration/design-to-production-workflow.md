# 从门窗设计到生产执行：订单、发布与变更方案

版本：0.13（2026-10-02，同订单行跨批统一变更已接入；人工验收及企业规则待确认）

## 1. 范围与现状

完整交付范围再次确认：这是设计研发使用的图纸工具，也是标准产品复用、定制需求研发、订单制造包会签、生产变更及受控先行/后补设计的共同技术底座。必须有真实岗位登录及对应工作界面、HTTP通讯、明确JSON契约和后端文件保存/加载，不能仅交付静态页面或单条标准订单演示。早期“权限、订单后置”的阶段性约定已由2026-10-02用户范围升级覆盖；真实工厂规则未验证仍不能对外宣称可正式投产。

本方案面向门窗厂的标准品、非标定制和生产中工程变更。当前PC画布、`DesignDocument.revision`、本地历史和工厂图是**设计草稿能力**；它们不等于产品发布版本、生产订单、已批准MBOM或车间实际记录。现有几何、对象ID、目录快照、BOM/工艺提取与图纸投影继续复用，不从SVG/3D反算物料。可选墙体/洞口绘图区是安装与方案场景，不是所有工厂设计的前置步骤，也不自动成为产品BOM。

生产订单必须引用一个不可变、已批准的制造基线；设计草稿和预览BOM不能下达。真实供应商截面、扣尺、孔槽、物资和工艺规则未验证时，应阻断正式生产发布，不能以模拟模板代替。

## 2. 核心对象与版本

| 对象 | 职责 | 版本/身份原则 |
| --- | --- | --- |
| `ProductDefinition` / `FactoryProductRelease` | 可重复使用的标准门窗设计、允许的参数化选项、图纸和技术定义/目录引用 | 产品号与发布版本独立；已发布版本不可覆盖，停用不删除历史 |
| `Order` / `OrderLine` / `RequirementSnapshot` | 客户要求、数量、洞口/尺寸、材质、交期和必要附件 | 订单及行有稳定ID；每次确认形成订单修订，冻结当时需求 |
| `EngineeringRequest` | 非标设计任务或已确认订单的设计变更任务 | 引用订单行和需求修订；保留评审意见与退回原因 |
| `DesignDraft` | 当前绘图文档及其草稿修订 | `DesignDocument.revision`只记录编辑过程，不可充当发布版本 |
| `DesignRelease` | 已审核图纸、对象图、产品参数、目录/规则版本与输入指纹 | 不可变；包含图号、发布版本、签核和被替代版本 |
| `BOMRelease` / `RouteRelease` | 与设计发布精确绑定的EBOM、订单MBOM、下料和工艺路线 | 保存计算规则/目录快照与审核状态；不能引用“最新”设计 |
| `ManufacturingPackage` | 某订单行/数量/交付批次的生产下达快照 | 冻结订单修订、设计发布、BOM、路线、编号及生效范围 |
| `ExecutionRecord` | 领料、加工、质检、返工、报废、替代等真实发生事实 | 追加记录，不随设计或制造包升级而重写 |
| `EngineeringChange` / `DeviationRecord` | 受控工程变更与现场偏差/先行执行 | 记录原因、关联基线、影响、处置、生效点和闭环证据 |

内部稳定对象ID、图面短编号、产品型号、物资编码、生产件号分别保存；图纸短号可按唯一性规则人工维护，但不能当内部主键。订单可多次引用同一个标准产品发布，逐单生成各自的制造包和正式生产身份。

## 3. 三条业务主线

### A. 标准品直接下单

`已发布标准产品 → 订单行选择产品版本和允许选项 → 校核尺寸/材质/数量/交付要求 → 冻结订单需求 → 按该订单生成并审核MBOM/路线 → 下达制造包 → 执行与质检`

标准品不是复制一张可任意编辑的旧图。超出发布产品允许范围的尺寸、材料或连接变化，自动转为非标工程请求；已发布标准产品本身保持不变。相同标准设计下的两张订单仍有不同的订单行、数量、批次和生产件号。

### B. 非标定制

`订单需求快照 → 设计研发领用EngineeringRequest → 用当前画布创建/改造设计草稿 → 几何/目录/图纸/EBOM预校核 → 工艺、采购、生产、质量会签与退回修改 → 客户承诺字段再确认 → 发布DesignRelease/BOMRelease/RouteRelease → 冻结订单修订 → 下达ManufacturingPackage`

评审可以多轮，但每轮必须指向确定的草稿修订与评审意见。工艺确认设备/工装和加工可行性，采购确认物料/替代及交期，生产确认装配顺序和产能，质量确认检验要求；设计研发负责修订图纸与计算来源。若变更影响外观、尺寸、价格或交付承诺，销售/客户确认应发生在生产下达前。会签通过后再产生不可变发布版本；不能把仅有“预览图”的产品标为可生产。

### C. 生产中变更

`客户/采购/工艺/现场提出变更 → 指定订单行、旧发布版本和受影响批次/工序 → 影响分析 → 新设计草稿及差异 → 重新校核和分岗审核 → 新设计/BOM/路线/制造包版本 → 生效点与旧在制品处置 → 车间接收变更并执行 → 质量验证与闭环`

差异至少覆盖几何/尺寸、材料型号、逐件数量和下料、工序/设备、采购与库存、成本/交期接口、已领料/已加工/已装配/已发运范围。生效点必须具体到订单行、批次/生产件、工单或工序，并明确旧件“照用、返工、报废、换件、隔离”的决定；不能简单把旧制造包改成新版本。受影响的未开始任务可切换到新包，已执行事实保留并关联处置记录，车间必须确认收到变更。

## 4. 先生产、后补设计的受控例外

现实允许“先行处置”，系统不能把它伪装成事前批准：

1. 由授权岗位创建`DeviationRecord`/紧急执行申请，记录真实发起时间、原因、适用订单与生产件、现场实际尺寸/物料/做法、风险和临时批准人；仅对指定范围放行，不改变标准产品目录。
2. 记录实际领料、加工、检验及隔离状态；没有明确的临时放行与质量控制时，不允许直接结案或标为正式放行。
3. 设计研发随后补绘/修订图纸，工艺与质量比对`as-designed / as-planned / as-built`，形成差异、返工或让步接收结论；保留真实时间线，不倒签、不覆盖现场记录。
4. 补签发布新设计/BOM/路线后，把实际生产件与该发布版本建立追认关系；未闭环偏差、未审批替代和不合格件仍显式阻断相应交付。

普通绘图用户不能单方启用该通道；需要责任岗位与质量/生产复核。紧急放行规则、批准矩阵和时限由企业配置，但追加式事实记录与禁止倒签是固定约束。

## 5. 状态、权限和界面

状态机分开，不能合成一个“订单状态”：

- 工程请求：`待分派 → 设计中 ↔ 退回修改 → 待会签 → 已通过/已拒绝 → 已发布`。
- 设计：`草稿 → 待审核 → 已发布 → 已替代/已停用`；退回产生新草稿修订，发布内容不可原地改。
- 订单行：`待确认 → 已确认 → 待制造发布 → 已下达 → 生产中 → 完工/关闭`；变更用新订单修订和关联请求。
- 制造包：`待计算 → 待审核 → 已冻结 → 已下达 → 已替代/完成`；输入版本变动则旧待审核包失效。
- 工程变更：`提出 → 影响评估 → 会签 → 批准/驳回 → 待切换 → 执行中 → 已验证关闭`。

登录后按岗位显示工作入口，而不是把同一个开发属性面板给所有用户：

| 岗位入口 | 主要可见/可执行能力 |
| --- | --- |
| 销售/订单 | 订单与需求录入、标准产品选择、客户确认、变更申请；不改已发布图纸和工艺 |
| 设计研发 | 设计任务、2D/3D画布、业务材料/型号、图纸差异、设计提交；不能自审自发生产 |
| 设计审核 | 图纸与规则完整性审核、退回/批准；审核具体修订 |
| 工艺工程 | 下料/孔槽/装配路线、设备/工装适配和工艺会签 |
| 采购 | 物料有效性、替代、缺料、交期与采购影响确认 |
| 生产计划/主管 | 制造包下达、生效切换、在制品处置与接收确认 |
| 车间执行 | 按生效版本查看工位图纸、扫码领料/报工、记录偏差；不能改设计基线 |
| 质量 | 检验、隔离、让步/返工验证及紧急先行处置复核 |
| 管理员 | 组织、用户、角色、编号与会签策略配置；不能以管理员身份跳过发布校核 |

一人可兼多个岗位，但“提交人不得批准自己提交的版本”等职责分离规则仍在服务端校验。认证、组织隔离、对象范围、动作与状态共同决定权限；前端隐藏按钮只是体验，不能代替服务端鉴权。审批、驳回、发布、下达及紧急放行均记录人员、时间、基线、决定与理由；留存不可覆盖的审计事件。

界面划分为订单工作台、工程任务与绘图工作台、图纸/BOM/工艺会签台、生产下达/变更切换台、车间/质量执行台、管理台。设计画布仍专注绘制，右侧属性仍面向设计构件；订单需求以可核对的只读输入快照进入设计任务，不把审批流程塞进画布工具栏。

## 6. 在现有仓库中的落地顺序与验收

1. **基础边界（下一里程碑）**：保留现有绘图命令和本地文件，新增上述聚合契约、不可变引用、输入指纹、状态机和多版本差异纯函数；旧本地文件迁移为未发布设计草稿。建立真实身份/岗位权限的最小服务端门禁后，才允许正式审批与下达。
2. **标准品纵切**：发布一樘经确认目录的标准窗；订单行固定其版本与选项；按数量生成独立、可追溯的订单MBOM和制造包；审核后下达。版本升级不改变旧订单。
3. **非标纵切**：从客户需求创建工程任务，经历至少一轮退回修改、工艺/采购/生产/质量会签、设计和BOM发布，并把结果固定回订单行。
4. **变更纵切**：生产开始后改一项尺寸或物料，展示图纸/BOM/路线差异和在制品影响，审批后按指定批次/工序切换；保留旧执行记录并验证接收。
5. **先行处置纵切**：记录先生产事实和临时批准，补图、追认或返工，证明时间线与`as-built`不可被后补设计覆盖。

每条纵切都要有旧版本重放、重复提交幂等、冲突拒绝、未授权拒绝、缺目录/工艺映射阻断和撤回/退回测试。实际企业的会签岗位、物资主数据、成本/交期、设备能力和编号规则需由目标工厂确认；未确认前可以构建流程与模拟夹具，但不能宣称“可投产”。

### 6.1 完整交付的业务验收口径

本次范围确认不等于追加一个订单表单，而是同一产品、需求、发布、制造包和实际生产件贯穿以下主路径。已有原型实现不等于人工验收完成，MS-BIZ-00至03保持DOING。

| 主路径 | 必须证明的结果 | 当前边界与后续任务 |
| --- | --- | --- |
| 标准件订单 | 选择明确的历史批准版，逐单按数量形成BOM和制造包；发布新标准版不改变旧订单 | 原型已接入；允许尺寸/选项范围、真实物资/规则和人工岗位验收仍待完成 |
| 定制研发 | 冻结需求进入任务，研发领用绘图；工艺、采购、生产、质量可以退回；修订后重新会签再发布 | 原型已接入；真实工厂模板、需求附件和企业审批矩阵需深化，不以预览BOM直接投产 |
| 生产工程变更 | 以该批实际生效版为基线，保存图纸/BOM/路线差异、受影响件号和工序；确认后下达并由车间接收 | 单批、连续修订及同订单行跨批统一会签/原子下达已接入；多订单联合方案和既有独立提案合并仍待扩展 |
| 先行生产后补 | 限定范围临时授权，保留真实实际记录；后补图纸与实际记录核对，处置与质量确认后闭环 | 有基线的受控先行已接入；没有任何图纸基线的紧急开工仍TODO，不能伪造事前批准 |
| 岗位工作台 | 销售维护需求；研发绘图；审核/工艺/采购/生产/质量处理本岗事项；车间查看生效包并执行 | 密码登录和服务端角色/状态检查已接入；人工逐岗操作验收、企业身份与正式部署仍待完成 |

四层版本必须分别保留：草稿编辑修订、批准产品/图纸发布版、订单修订及制造包版、追加式实际记录。生产订单与历史图纸是精确引用关系，不是自动追随“最新版”；标准产品目录、订单专用图纸和本机可复用模板不能混用。审核拒绝及修订清除旧会签，新设计不能覆盖已领料、加工或检验的事实。

近期在跨批统一方案基础上收口需求修订及其研发交接，再进行标准/定制/变更/先行四条岗位闭环验收；不转去包装运输等支线。真实截面、扣尺、孔槽、供应商物资、设备和采购/库存接口随后按业务边界接入，未经验证继续阻断正式投产。绘图和材料映射的既有人工门禁保持，不被业务原型测试替代。

## 7. 可执行原型与配置

2026-10-02已新增真实HTTP/文件服务、密码登录及岗位工作台。标准订单、定制需求/研发任务、图纸/BOM会签、制造包审核与执行、版本差异和变更切换、先行授权与补图对账均可进行流程演练。绘图文档和BOM算法继续复用共享核心，不从显示图形反算制造数据。工艺岗位可维护路线顺序、加工说明与模板引用，修改后清除会签并重新提交。生产包自带锁定版本图纸、逐件BOM和路线，禁止跳过前序工序。

先行处置现在必须明确生产件号、允许工序、风险和控制措施。生产与质量分别批准；超出范围或省略授权关联不能作为正常报工绕过。退回申请由原申请人修订，清除旧签名重新会签；未授权且未执行的申请可以撤回，保留原申请、审核和撤回记录。已授权的范围不能直接改写。后补图变更必须覆盖全部授权生产件，关闭偏差前须具备范围内每个生产件、每道工序的实际记录及已闭环补图变更。执行时间由服务端追加，不倒签；归档保留各轮申请与意见。旧版本缺少scope的先行申请不默认视为整包授权。

标准产品使用共享的完整规格摘要，不再仅读取第一樘窗。组合尺寸来自共享展开外廓并计入连接件；多个独立产品作为一套下单时，总宽是单元展开宽之和、总高是最高单元，不含现场摆放间距；这不是安装总尺寸。发布快照列出每樘尺寸、型号、内外颜色和每个产品单元。订单入口使用同一计算自动带入字段，后端按整套规格校验；仅忽略大小写与空白，不把RAL与十六进制颜色伪认为等价。型号/颜色/尺寸变化须选择定制；选择历史发布作为定制参考会保留多窗与连接原构造，订单需求由研发核对调整，不能自动把整套产品替换成单个矩形窗。允许的参数化选项及供应商颜色等价映射仍后续扩展。

定制任务状态为待分派→待领取→设计中→会签/退回→发布。设计审核或生产主管可分派/交接给本工厂启用的研发账号；研发可领取未分派任务或分派给自己的任务。只有实际领取者可保存、提交或发布任务图纸。交接仅在草稿/退回阶段进行，清除领取状态，接收人需重新领取；会签中不能改负责人。工艺人员仍可维护加工路线，不冒充任务负责人；人员目录只返回启用账号的身份与岗位，不返回登录名或密码摘要。分派、领取及交接均随JSON修订归档。

同一订单行现在可以按整套数量分批建立制造包，每批固定图纸/BOM/路线并独立会签、下达、接收和执行。服务端检查整数数量、剩余可分配数量和订单行内批次名唯一性；未指定数量兼容旧命令，默认分配剩余数量。变更新包通过`supersedes`消费已有生产件，不重复占用订单数量。所有订单行数量全部分配且有效制造包全部完成后，订单才完工；不能以第一批完工代替整单完工。

工程变更新增`dispositionRecords`逐件旧件处置证据：原件号、沿用/返工/报废/替换/隔离、实际执行记录ID、替换新旧件号对应、去向说明、记录人和服务端时间。返工/报废必须关联范围内逐件成功实际记录；替换关系必须一对一且不能复用已确认新件号。操作员或主管登记，生产和质量两位独立人员确认，登记人不得自审，兼岗人员不得跨岗重复确认。退回记录保留，需另补新记录，定稿不能覆盖。隔离是临时状态，须补充沿用/返工/报废的最终结果并重新确认；替换须在变更方案中批准，不能以隔离放行绕过替换件号生成。全部旧件最终处置确认及全部新件最新终检合格后才能闭环。已完工原包只允许追加已接收变更范围内的返工/报废，不重开旧图正常加工；原实际记录保留。

发布快照新增`scope`：`catalog`是可供标准订单复用的标准产品；`order-line`绑定具体订单和订单行，供定制任务及生产变更使用。订单专用图纸不能直接作为标准产品下单，也不能通过普通目录修订绕过制造包生效范围；复用其构造须建立新的定制需求。标准产品修订仍要求最新标准目录基线，但订单变更可从该批次实际锁定的旧版本分支；不因另一订单已发布新版本而强制换用。旧快照缺少scope时根据工程任务、变更及发布父链推断，不改写历史文件。旧数据中已被早期逻辑改写的订单默认版本不自动猜测恢复，须核对归档基线。

每个变更独立保存`customerConfirmation`，不同批次的新图纸不会相互覆盖客户确认。下达变更只建立该件号范围的新制造包，不修改订单行原始图纸默认值；未受影响批次和未分配数量继续引用原基线。空件号输入在创建时固化为原包当前有效件号，不能随后扩大；同一原包可并行处理不相交范围，重叠申请被拒绝。已切换件号不能再从旧包发起改图，连续修订须在上轮变更闭环后从当前生效包发起。影响评估只比较受影响件号的实际记录，范围内新增报工导致旧会签失效，其他件号报工不使本变更误过期。

未下达变更允许发起人撤回，保存原因、人员、时间以及已有图纸、会签和客户确认，不删除历史；释放预留件号并禁止继续编辑、确认或下达该方案。已下达变更不能撤回。已关联的先行偏差解除当前补图关联但保留授权与实际记录，需另建有效方案追认，不能把撤回视为偏差闭环。

`usage=prototype`、`basis=reference-simulation`、`productionEligible=false`固定由后端写入；原型“发布/下达”不是实际投产授权。人工视觉验收、企业真实截面/扣尺/孔槽/设备规则、标准产品参数化允许选项及供应商颜色等价映射、复杂排产/整单取消与已下达批次的数量取消处置、多订单联合变更及既有独立提案合并、需求附件/修订深化、零件级库存与报废采购凭证接口、实际采购/设备接口、无图纸基线的紧急开工、完整租户/资源隔离及正式部署仍TODO，不宣称全部完成。当前处置关联生产成品件号及实际记录，并非零件库存账。

### 同订单行跨批统一变更（2026-10-02）

订单行出现至少两个有效已下达批次时，订单页提供“跨批统一变更”。可纳入2至200个同产品、同订单行的原包或已闭环修订包，各批可以有不同的旧发布版。首次纳入批次提供共享图纸基线；当前不把多产品或多订单强行套进一张共享图纸，也不直接合并既有独立提案。

工作区新增可选集合`changeSchemes`，每项为`{id,name,createdBy,createdAt,changeIds}`；批次变更新增可选`schemeId`。首个成员的`changeId`拥有唯一共享设计；所有成员共用当前设计、目标发布、客户确认和五岗会签，各自保留原制造包/原发布版、差异、件号、生效工序、处置及实况影响。共享发布的父版是实际绘图基线，不能伪称同时继承各批旧图；成员差异分别对比各自原发布。至少一批有差异才可提交，其中已符合目标的一批允许无差异。

创建命令示例（仍需外包`expectedRevision/idempotencyKey/command`）：

```json
{
  "type": "create-change-scheme",
  "name": "同一产品两批尺寸修订",
  "reason": "客户调整",
  "procurement": "核对新材料需求",
  "cost": "核对差额",
  "delivery": "核对交期",
  "scopes": [
    { "packageId": "原批A的ID", "batch": "A", "fromStep": "CUT", "pieceNumbers": ["A件号"], "disposition": "use-as-is" },
    { "packageId": "原批B的ID", "batch": "B", "fromStep": "MATERIAL", "pieceNumbers": ["B件号"], "disposition": "replace" }
  ]
}
```

空件号列表在创建时固化为该包当前有效件号；原包重复、跨订单行、未闭环来源变更、已切换件或预留范围重叠均拒绝，失败不留下部分成员或孤立设计。

- `submit-change-scheme / refresh-change-scheme-impact / revise-change-scheme / issue-change-scheme`：参数`schemeId`。
- `review-change-scheme`：参数`schemeId,role,decision,note`，一次结论覆盖整组；退回整组回设计阶段，再修订只创建一份共享草稿并清除旧目标确认。
- `withdraw-change-scheme`：参数`schemeId,note`，仅发起人可撤回未下达整组；保留旧图纸/会签/确认与先行事实，解除当前补图关联但不撤销已授权范围。
- 图纸仍使用原设计提交/审核/发布接口；客户确认仍使用`confirm-customer`，服务端传播同一确认到整组。
- 成员的普通提交/修订/影响刷新/会签/撤回/下达接口被拒绝；下达后仍逐批使用`acknowledge-change`、处置登记/确认、`close-change`，不以一批闭环代表全组闭环。

整组下达在同一快照上校验所有成员的会签、客户版本、目标工序、有效件号、重叠范围及最新实况引用；一批`STALE_IMPACT`就整组409且不写文件、不增加订单修订。整组更新实况后全部重新会签。成功在一次后端事务中产生各批新制造包，订单只修订一次，幂等重试不重复建包；原订单默认图纸、其他件号、旧图纸/BOM/路线与实际记录不覆盖，替换包不重复占用订单数量。

加载/保存校验组与成员双向引用、唯一原包、同订单行/产品/共享设计、共同会签/客户确认/撤回记录，以及下达时一致的订单修订和提交时间；不能保存部分下达或孤立成员。方案状态只读派生为设计/会签/批准/下达/部分接收/部分闭环/全组闭环。旧文件没有集合时不补造统一方案。

### JSON协议与接口

类型契约在`packages/contracts/src/factory-workflow.ts`；命令JSON Schema在`packages/contracts/src/factory-command-schema.ts`，通过`GET /api/factory/schema`获取。工作区JSON Schema在`packages/contracts/src/factory-workspace-schema.ts`，通过`GET /api/factory/schema/workspace`获取，适用于工作区响应及文件中的workspace。绘图`document`仍执行`doormes-domain.v1`正式校验；不建立第二套图形格式。

服务端在写入、启动恢复及读取历史版本时同时校验字段和业务引用：图纸/发布/订单行/任务/制造包/变更/先行/实况之间的引用、唯一编号、产品与制造包父链、批次数量、工序与件号范围、会签修订和职责分离、冻结BOM/路线/加工参数与发布的一致性、事件及幂等回执目标。历史文件名须与内容revision一致。账号文件检查字段类型、角色和唯一身份/用户名；错误账号不默认选择第一个匹配项。字段或引用损坏即报CORRUPT_FILE并保留文件，不猜测修复、重新算料或补写审批。新增可选旧字段仍保持缺失，不自动成为授权。

文件SHA-256只检查内容完整性，不是数字签名或防篡改认证；结构和引用校验也不能证明人工维护的源文件真实可信。正式部署仍需受控存储权限、备份及发布签名策略。处理参数当前保留共享算法结构，尚未另建每个供应商加工模板的完整Schema。

```json

  "expectedRevision": 12,

    "type": "review-design",
    "designId": "backend-design-id",
    "role": "process",
    "decision": "approve",
    "note": "切割及装配可行性已核对"

```

文件封装为`{ "schemaVersion": "doormes-factory-file.v1", "checksum": "sha256", "workspace": {...} }`。当前快照以同目录临时文件重命名替换；归档只追加。启动校验文件及图纸，完整归档早于当前指针的中断可恢复；损坏文件保留并报错，不能用空数据覆盖。
