路线：门窗绘图可视化与材料映射优先，工厂生产/门店安装作为输出支撑  
当前里程碑：`MS-01 生产映射与业务目录核心收口`

## 1. 总体目标

> 2026-09-20执行边界修订：当前建设对象是“门窗绘图可视化工具”，
> 主线为2D绘制、3D展现、构件/连接/运动、交互、多端复用以及图形到
> 材料/BOM/工艺的映射。工厂生产和门店安装用于指导数据边界和验证输出，
> 但采购、排产、订单、安装任务、账号权限及完整三模式工作流当前不实施。
> 下文相关内容保留为总体目标，不得抢占当前绘图功能迁移顺序。

> 2026-09-22客户范围修订：目标客户固定为智宬轩系统门窗，窗型/门型/阳光房模板及目录优先级以`customer-target-zcsung.md`登记的公开产品谱系为依据。公开营销资料只能生成带来源状态的模拟模板；企业正式截面、物资、五金和工艺数据未签认前，不得形成可投产结论。

在不复制几何、2D/3D、开启运动和BOM算法的前提下，将原型升级为可扩展的DoorMes正式项目：

1. 开发模式能够定义并发布版本化的几何构件、关系/约束、渲染资产和生产映射；
2. 工厂模式能够设计单樘及工厂组合产品，完成选材、出图、BOM、采购/备料、加工、组装质检、包装和生产下达数据；
3. 门店模式能够建立安装环境、完成整体效果预览、业务选型、报价/销售订单、复尺和基础安装执行；
4. 三模式通过不可变版本、变更请求和影响报告交接，历史订单与制造记录可重放、不漂移；
5. PC、手机和平板使用不同交互壳，但共享同一领域模型、命令、渲染投影和制造结果；
6. 原型已有界面与功能最终全部迁移，审计发现的不合理或缺陷持续记录，不用错误原型行为污染正式核心。

## 4. 统一里程碑完成定义

任何里程碑只有同时满足以下条件才可标记`DONE`：

1. **代码**：领域、命令、应用服务、PC/移动壳和适配器依赖符合边界，没有把DOM/Three对象写入领域模型；
2. **数据**：Schema、默认值、旧版本迁移、不可变快照、稳定ID和损坏数据保护完成；
3. **结果**：2D、3D、对象树、BOM、工艺、版本和变更状态从同一输入得到一致结果；
4. **注释**：新增公共对象和函数说明作用、输入输出、调用关系、关键算法/约束、使用示例、版本及修改记录；复杂公式必须说明单位和边界；
5. **自动验证**：`npm run typecheck`、`npm test`、`npm run build`通过，相关旧夹具无非预期变化；
6. **人工验收**：提供明确URL/场景/输入/预期结果，由用户检查真实鼠标、触控和视觉效果；未经人工确认的门禁保持`DOING`；
7. **文档**：任务状态、功能矩阵、实现记录、已知缺口、审计问题和下一步同步更新；
8. **边界**：不借里程碑提前引入账号权限、远端基础设施或完整BIM，除非它们成为用户新确认的当前范围。

## 5.1 MS-01：生产映射与业务目录核心收口

状态：`DOING（自动实现完成，等待人工验收）`  
任务：`APPEAR-004`、`BOM-009`、`CAT-001`  
目标：在已经完成的玻璃SKU链基础上，补齐包边/衬板和五金业务型号，统一“业务目录项 → 展示/模型 → 物资 → 工艺 → BOM状态”。

### 交付物

1. 包边/衬板目录项及不可变选择快照：业务ID、精确版本、名称、规格、适用范围、物资编码、外观和加工映射；
2. 五金目录项及不可变选择快照：具体型号、适用角色/系列、物资编码、真实模型资产、毫米包络、连接/孔槽模板和表面外观；
3. 原子选择命令：一次提交同时更新业务选择、渲染/模型和生产映射，可撤销/重做；
4. 共享解析器：2D、3D、碰撞、BOM和工艺读取同一冻结快照，不依赖实时目录；
5. BOM状态规则：纯视觉调整保持`current`，物资/型号/处理/加工模板变化转`stale`，撤销可恢复；
6. 项目保存/恢复和旧数据兼容：目录后来修改或缺失时，历史设计仍按冻结版本恢复；
7. 缺映射诊断：展示模型可预览，但缺物资或加工模板时明确阻断生产确认；
8. 进度文档和企业真实目录待提供项清单。

### 实施顺序

1. 先完成包边/衬板目录Schema、参考数据和选择快照；
2. 接入共享选择命令、2D/3D外观及安装EBOM/切长/表面处理；
3. 再完成五金业务型号Schema，将既有GLB资产、角色/单件覆盖和连接模板纳入同一目录项；
4. 接入五金BOM、加工特征、碰撞和项目恢复；
5. 最后统一制造输入指纹、过期提示和重算入口，补回归夹具。

### 自动退出标准

- 包边/衬板和五金各至少两个版本化参考目录项，覆盖切换、撤销、恢复和目录脱离计算；
- 相同业务选型在PC/移动产生相同领域快照、2D/3D元数据、BOM编码和工艺模板ID；
- 纯颜色/粗糙度变化不改变制造输入哈希；物资、型号或生产表面变化使BOM准确过期；
- 无生产映射的预览项不能被确认或导出为正式制造包；
- 既有七组原型夹具无非预期数量/尺寸变化；
- 类型检查、全量测试和生产构建通过。

### 人工验收节点 `GATE-CATALOG-MAPPING`

在固定窗、单扇和双扇样例中分别切换包边/衬板材料和一件具体五金型号，检查：

- 业务名称/编码/版本正确；
- 2D、3D和对象树同步；
- 真实GLB或参数化降级体正确；
- EBOM/MBOM、加工模板和BOM状态同步；
- 刷新、项目导出/导入、撤销/重做后结果不漂移；
- PC与移动壳不出现横向溢出或技术字段误暴露。

### 本节点不包含

- 最终工厂业务选择器布局（属于MS-04）；
- 开发定义发布界面（属于MS-03）；
- 账号、权限、审批和远端目录服务。

依赖：MS-01目录快照边界稳定  
目标：在继续拆分工作区之前，先冻结门店/工厂/开发模式、文档聚合、字段能力和跨模式变更协议，避免后续重构核心数据。

### 交付物

1. `WorkspaceMode = store | factory | development`及模式上下文，现有项目默认迁为`factory`；
2. 三种文档聚合和引用契约：`DefinitionWorkspaceDocument`、`FactoryDesignDocument`、`StoreProjectDocument`；
3. 版本链：`DefinitionPackageSnapshot → FactoryProductRelease → StoreProductConfiguration/SalesOrder → ManufacturingPackage → InstallationTask`；
4. 字段可见/可编辑和命令能力矩阵；
5. `ChangeSet`、`ChangeRequest`、`ImpactReport`、`ReleaseRevision`、`DeviationRecord` Schema和纯状态机；
6. 基础修订冲突、不可变发布、`stale/reconfirmation-required/superseded`传播规则；
7. 本地仓储和项目文件版本迁移；
8. 最小模式路由/调试入口，用于证明壳层切换不改变领域结果。

### 实施顺序

1. 定义模式、聚合ID和不可变引用，不先做完整界面；
2. 编写能力矩阵和命令守卫，明确门店/工厂/开发各自可修改字段；
3. 实现变更对象、状态机和影响标签纯函数；
4. 把现有DesignDocument兼容迁为工厂文档，并验证项目文件往返；
5. 增加版本冲突、显式升级、订单重确认和偏差限定测试；
6. 最后接入最小路由和差异/影响调试视图。

### 自动退出标准

- 旧正式项目无需用户操作即可加载为工厂模式，保存后仍可由兼容解析器读取；
- 模式切换不改变产品JSON、制造输入哈希、BOM或2D/3D结果；
- 错误模式执行受限命令得到结构化拒绝，不产生半次修改；
- 开发新版本不自动升级历史产品；已确认订单不能原地修改承诺字段；
- 两个基于同一旧`baseRevision`的冲突变更不会“最后写入覆盖”；
- 生产/安装偏差只引用指定实例或批次，不修改目录和产品模板；
- 类型检查、全量测试和生产构建通过。

### 人工验收节点 `GATE-MODE-CHANGE-CORE`

- 在最小入口切换门店/工厂/开发，观察可见字段和允许操作不同；
- 同一产品在三个壳的2D/3D和只读BOM一致；
- 模拟开发定义升级，历史产品保持旧版本并显示可升级提示；
- 模拟订单确认后的尺寸变化，系统生成变更请求和影响报告，不覆盖原订单；
- 模拟生产偏差，确认只影响指定生产件。

### 本节点不包含

- 登录账号和真实岗位权限；
- 三个模式的完整业务页面；
- 远端事件总线、数据库和多人实时协同。

## 6.2 后续目标（当前不执行）：开发定义包最小闭环

状态：`DEFERRED`  
任务：`DEV-001至004`、`CAT-003`  
依赖：MS-02  
目标：把目前散落在代码和高级编辑器中的构件、渲染、模型和生产映射整理为可验证、可版本化发布的技术定义，不让门店/工厂用户接触底层技术属性。

### 首个参考定义包

选择现有AL70参考系列做最小覆盖，至少包含：

- 一个框/梃型材构件定义；
- 一个玻璃/固定区域定义；
- 一个开启扇及侧铰连接定义；
- 一个执手或锁具型号资产定义；
- 对应物资、切割、孔槽/安装和表面处理映射。

### 交付物

1. `ComponentDefinition`参数Schema、单位、默认值、允许范围和示例；
2. `PortDefinition/ConstraintDefinition`锚点、连接兼容、尺寸、拓扑、宿主、运动和碰撞约束；
3. 2D符号/尺寸锚点/命中区及3D参数化或GLB、包络、轴向、枢轴、材质槽、LOD定义；
4. `ManufacturingMapping`到物资、下料、孔槽、组装、质检和包装特征；
5. 技术目录工作区：草稿、差异、预览、样例、校验、发布和历史版本；
6. 定义夹具：输入、预期几何、2D/3D快照、BOM/工艺和错误样例；
7. 显式迁移器和发布门禁；
8. 当前PBR/UV/GLB高级编辑能力迁入开发工作区，工厂普通入口不再展示。

### 自动退出标准

- 无效单位、循环宿主、不可连接端口、越界枢轴或缺生产编码的定义不能发布；
- 已发布定义不可编辑，只能复制为新草稿版本；
- 同一夹具通过Schema、约束、2D、3D、BOM和工艺联合验证；
- 发布新版本不改变引用旧版本的工厂产品；显式升级后输出完整影响报告；
- 定义只引用已注册策略ID，不执行任意上传脚本；
- 类型检查、全量测试和生产构建通过。

### 人工验收节点 `GATE-DEFINITION-PACKAGE`

在开发模式复制参考定义，修改一个可见材质参数和一个生产映射参数，分别预览差异、运行样例并发布新版本；回到工厂模式后，旧产品保持不变，选择升级的副本同步改变2D/3D与BOM并显示影响范围。

### 本节点不包含

- 面向第三方的通用插件SDK；
- 在线脚本运行和插件市场；
- 账号审批与数字签名。

## 6.3 后续目标（当前不执行）：工厂业务选型与产品发布最小闭环

状态：`DEFERRED`  
任务：`CAT-002`、`FACTORY-001`、`ASSEMBLY-001/002`、`BOM-010`  
依赖：MS-03  
目标：让工厂设计人员只通过业务型号和产品参数完成设计，并将一樘开启窗和一组直线拼樘冻结为可追溯产品与制造包v1。

### 交付物

1. 工厂业务选择器：系列、型材、玻璃、五金、表面处理、包边/辅件，只显示名称、编码、规格、适用范围和预览；
2. 产品校核汇总：尺寸/拓扑、开启碰撞、连接、目录映射、BOM/工艺模板和交付接口；
3. `FactoryProductRelease`：冻结产品/组合结构、业务选型、定义版本、输入哈希和交付安装接口；
4. `FabricationAssembly`最小实现：单樘实例、直线左右拼樘、连接端口、拼樘料/加强/连接件/密封和包装拆分意图；
5. `BOM-010`确认/冻结/变更版本状态机；
6. `ManufacturingPackage v1`：EBOM/MBOM、采购汇总、净下料需求、加工特征、生产身份和来源追溯；
7. 产品发布、复制为新版本、变更影响和历史回放界面；
8. 一樘开启窗和一组直线拼樘的冻结验收夹具。

### 自动退出标准

- 工厂选择器不出现PBR、UV、哈希、模型枢轴、约束表达式和孔槽模板编辑字段；
- 缺必需物资或工艺映射、无效拓扑、关闭不贴合或运动碰撞时禁止发布；
- 单樘物料在组合BOM中不重复，拼樘新增物料只计算一次；
- 相同规格的两个产品实例拥有不同生产身份；
- 制造包输入相同时输出和哈希确定一致，冻结后不能原地修改；
- 新产品版本不会改写历史制造包；
- 类型检查、全量测试、原型夹具和生产构建通过。

### 人工验收节点 `GATE-FACTORY-RELEASE`

1. 用业务选择器完成一樘内开内倒窗的型材、玻璃、五金和颜色选择；
2. 检查2D、俯视、3D、开启、对象树和尺寸；
3. 查看产品校核并冻结产品与制造包；
4. 将两樘窗建立直线拼樘，检查总体尺寸、连接件、组合BOM和包装拆分；
5. 修改已发布产品时确认系统要求新版本，旧制造包仍可查看和重放。

### 本节点不包含

- 优化下料、完整工位路线、质检和包装执行（属于MS-05）；
- 门店报价、订单和安装场景（属于MS-06）；
- 普通推拉及后续窗型完整迁移（属于MS-07）。

## 6. 中远期里程碑边界

### MS-05：工厂制造执行数据闭环

总体交付：制造包确认后形成备料/缺料、型材定尺优化、余料、加工路线、工位指导、逐件生产号、装配顺序、检查点、包材加工、包装单元、标签和出厂清单。详细目标在MS-04通过后，结合企业真实原料定尺、设备/刀具、工艺模板和包材规格再展开。

### MS-06：门店销售安装最小闭环

总体交付：一墙一洞一窗、环境材质、整体安装预览、允许产品配置、报价/订单、标准品制造交接、非标工程请求、复尺、包装交付核对和基础安装执行。详细目标在`FactoryProductRelease`与`ManufacturingPackage`格式冻结后展开。

### MS-07：原型剩余功能完整迁移

总体交付：推拉、提升/平行/PSK、入墙/转角/上下提拉、折叠、纱窗、填充、异形、文字/标记、工程节点和组合。每类必须交付领域、命令、2D、3D、PC、移动、BOM、工艺、包装输入、测试和迁移说明，不接受只有可视化的半切片。

### MS-08：正式功能验收

总体交付：桌面、手机、平板功能矩阵关闭；真实设备、性能、资源释放、项目文件、旧数据迁移和视觉回归完成；形成最终迁移验收报告。用户保留真实鼠标/触控手感与最终视觉签审。

### MS-09：治理与部署

总体交付：在核心功能签审后接入账号、组织、权限、审批、审计、远端目录/对象存储、数据库、正式部署和备份；是否扩展完整建筑BIM及多承包方施工协作另行立项。

## 7. 里程碑变更规则

1. 新需求先判断属于现有里程碑、后续里程碑还是范围外；
2. 若改变共享模型、版本链或制造算法，必须先更新依赖和退出门槛，再开始编码；
3. 人工测试缺陷插入当前里程碑修复，不因为验收等待而停止无依赖工作；
4. 企业真实目录或设备数据未提供时，可用明确标记的参考数据验证契约，但不得宣称生产规则已签审；
5. 里程碑只有验收门通过后才能切换当前节点；未完成项必须带任务ID进入下一版本，不能只写“后续完善”。
