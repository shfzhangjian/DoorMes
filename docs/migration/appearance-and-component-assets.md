# 材质、颜色与自定义构件模型方案

文档版本：0.25.4
状态：共享高级编辑能力完成，玻璃、包边/衬板和五金业务目录映射已形成可人工验收切片；设计/技术界面分层继续；账号/权限/审批/生产部署后置

## 1. 目标与范围

正式项目必须允许墙体、窗框、窗扇、玻璃、飞梃、包边和五金分别配置可渲染材质与颜色。锁具、执手、合页、锁点/锁座及后续辅件除外观外，还必须支持不同型号的几何形状，并允许用户在受控规则下使用自定义模型。

当前阶段只实现用户可见、可操作、可保存、可重放并能正确影响2D/3D/BOM的业务功能。已经存在的权限与审核类型只保留为未来接口，不继续扩展，也不作为本阶段完成门；账号登录、用户角色、审批流、操作审计和生产基础设施统一在功能迁移完成后实施。代码中的`role`只表示执手/合页/锁点等“五金构件类型”；用户界面统一称“构件类型”，不再显示容易与账号权限混淆的“五金角色”。

该能力不是Three.js局部换色功能，而是“版本化外观快照 + 构件型号目录 + 渲染资产”的完整链路：

```text
材料/五金目录
  → 设计对象保存版本化外观与型号快照
  → 几何层解析构件角色、安装锚点和实际尺寸
  → SVG使用同一颜色/符号降级
  → Three使用PBR材质与参数化/模型资产
  → 制造规则按目录映射物资编码、表面处理和加工模板
```

PC和移动端只提供不同编辑布局；材质、颜色、型号、模型定位、BOM映射和校验规则必须复用同一核心。

同一外观/型号快照按交付目的采用不同表达：Three.js在3D真实仿真中使用完整PBR、纹理、透明玻璃和参数化/GLB构件模型；SVG工程设计视图只保留便于识别和编辑的基础色、透明度、标准符号或工程填充；工厂/安装技术图纸则以物资编码、规格、表面处理代码、构件型号、标准填充和材料表作为权威信息。彩色效果页或3D快照可以作为沟通附件，但纹理和屏幕颜色不得替代生产/安装说明，也不得成为BOM身份。

## 2. 业务对象分层

### 2.1 外观不等同于物资

- `materialCode`回答采购和生产中的物资身份。
- `appearancePresetId`回答当前如何显示及其表面处理快照。
- `componentModelId`回答锁具等构件使用哪一种物理外形和安装锚点。
- `assetId`只定位纹理或3D资源，不能直接充当物资编码。
- 当颜色、喷涂、覆膜、木纹或锁具型号会改变价格、采购或工艺时，版本化规则必须把设计选择映射到新的物资编码/表面处理特征；纯展示选择不得擅自修改BOM。

### 2.2 已落地领域契约

```ts
interface VisualAppearanceSnapshot {
  appearanceId: string;
  appearanceVersion: string;
  baseColor: string;
  materialFamily: "metal" | "glass" | "wood" | "stone" | "plaster" |
    "brick" | "plastic" | "rubber" | "custom";
  metalness: number;
  roughness: number;
  opacity: number;
  textureSetId?: string;
  uvScale?: { x: number; y: number };
  finishCode?: string;
  productionMapping?: SurfaceProductionMappingSnapshot;
}

interface SurfaceProductionMappingSnapshot {
  schemaVersion: "doormes-surface-production.v1";
  productionStatus: "preview-only" | "catalog-approved";
  treatmentCode?: string;
  processTemplateId?: string;
}

interface SurfaceAppearanceAssignment {
  outside: VisualAppearanceSnapshot;
  inside: VisualAppearanceSnapshot;
  edge: VisualAppearanceSnapshot;
}

interface HardwareComponentModelSnapshot {
  modelId: string;
  modelVersion: string;
  geometry: ParametricComponentGeometrySnapshot | GltfComponentGeometrySnapshot;
  dimensionsMm: { widthMm: number; heightMm: number; depthMm: number };
  mount: {
    pivotRatio: { x: number; y: number; z: number };
    mountAxis: "+x" | "-x" | "+y" | "-y" | "+z" | "-z";
  };
  appearance: VisualAppearanceSnapshot;
  fallbackSymbolId: string;
  productionStatus: "preview-only" | "catalog-approved";
  materialCode?: string;
  machiningTemplateId?: string;
}
```

实现位于`@doormes/contracts`与`@doormes/appearance-model`。窗口保存完整`WindowVisualConfiguration`；五金按角色保留默认型号，并允许用稳定`hardwareId`覆盖单个锁具。解析顺序为“精确五金优先，角色默认兜底”。历史设计不能因目录或远端模型更新而改变外观、尺寸或安装位置。

### 2.3 设计业务选型与技术维护必须分开

同一份目录数据服务两类功能，但不得用同一套字段直接面对两类用户：

| 功能入口 | 主要使用者 | 展示和可编辑内容 | 明确隐藏内容 |
| --- | --- | --- | --- |
| 设计业务选型 | 门窗设计人员 | 系列、业务名称、物资/型号编码、规格、颜色/表面名称、适用窗型/型材、供应商信息、缩略预览和可选组合 | PBR数值、UV重复、纹理哈希、GLB轴向/枢轴、LOD、加工模板内部字段 |
| 技术目录维护 | 产品/技术/开发维护人员 | 业务目录项到外观快照、纹理资产、UV、模型资产、真实尺寸、轴向/枢轴、物资编码、表面处理和加工模板的版本化映射 | 不隐藏底层参数，但必须校验并区分“仅展示”和“影响生产” |

设计人员选择的是一个明确的业务目录项，而不是手工拼装渲染参数。解析器再把该目录项转换为2D/3D外观、模型和BOM/工艺映射。设计文件保存目录项ID、精确版本及其不可变快照，避免目录升级后历史订单漂移。

当前PC/移动三步外观与模型编辑器是迁移期高级工具，也是未来技术目录维护界面的能力基础，不是最终的日常设计选型界面。0.10.25已在界面明确提示此边界；CAT-002负责业务选型，CAT-003负责承接高级参数维护。本阶段先完成两类功能入口、数据映射和本地校验，不提前引入账号、权限和审批。

UV重复是可预先配置的材质属性，不依赖当前是否已经绑定纹理资产：目录维护可先保存倍率，渲染器在纹理可解析后再消费。界面不得因为暂时是纯色而静默删除倍率或重置为`1 × 1`。

## 3. 适用对象

| 对象 | 外观能力 | 几何/型号能力 | 制造影响 |
| --- | --- | --- | --- |
| 墙体 | 抹灰、混凝土、砖、石材、自定义纹理和颜色 | 当前矩形宿主；后续墙角/墙腔 | 默认仅现场宿主，不进门窗产品BOM |
| 窗框/窗扇/中梃/飞梃 | 内外颜色、金属/木纹/塑料、粗糙度、纹理和表面处理 | 截面仍由型材目录决定 | 颜色/表面处理可映射型材SKU或工艺特征 |
| 玻璃 | 颜色、透明度、反射/粗糙度、Low-E视觉层 | 厚度和组合由玻璃规格决定 | 必须保持玻璃规格、厚度和物资编码一致 |
| 包边/衬板 | 内外颜色、板材/金属/木纹 | 实际板厚和宽度来自Installation | 可改变安装物料和表面处理 |
| 锁具/执手/合页/锁点 | 独立颜色、金属度、粗糙度、涂层 | 参数化形状或版本化glTF型号，可自定义 | 型号必须映射五金物资编码、安装位和加工模板 |
| 辅助线/标尺/选中框 | 主题颜色 | 无生产几何 | 永不进入BOM |

## 4. 自定义锁具和五金模型

### 4.1 支持方式

1. 内置参数化模型：矩形锁体、杆式执手、圆柱旋钮、合页叶、锁点和锁座，可输入实际宽高深、圆角、杆长等参数。
2. 目录模型：供应商发布的版本化glTF/GLB资产，目录同时给出物资编码、真实尺寸、安装锚点、方向、适用型材和加工模板。
3. 用户自定义模型：上传GLB/glTF后必须经过单位、轴向、包围盒、三角面数、材质、纹理和安全校验，再由用户确认安装面、枢轴和实际毫米尺寸。未经发布的模型只能用于设计预览，不能自动获得可生产状态。

### 4.2 不允许的捷径

- 不允许把任意模型的原点直接当作安装点。
- 不允许用视觉缩放替代真实毫米尺寸；缩放后的尺寸必须形成明确快照。
- 不允许仅凭文件名推断物资编码或加工模板。
- 不允许SVG和Three各自保存不同型号；SVG使用同一`componentModelId`的标准符号或轮廓降级。
- 不允许远端资产覆盖同版本内容；资产必须有内容哈希、版本和缓存策略。

### 4.3 移动端约束

- 每个模型必须提供低模LOD或参数化替代形体；高模只在设备等级允许时加载。
- 纹理采用尺寸上限、压缩格式和复用缓存，禁止为同色构件重复创建纹理/材质。
- 模型加载失败时显示`fallbackSymbolId`对应形体，同时保留选择、BOM和安装锚点，不能让构件消失。
- 自定义模型编辑器在手机使用全屏分步流程，在PC使用设置面板，但提交相同完整命令。

### 4.4 受控导入、LOD与发布历史

PC面板和移动分步界面最终都调用`createManagedGltfGeometrySnapshot`，界面不能自行拼装坐标转换。导入快照保存以下内容：

- 源单位：毫米、厘米、米或英寸；
- 源上轴：`±X/±Y/±Z`之一，映射为DoorMes的`+Y`；
- 源朝向轴：与上轴垂直的有符号轴，映射为DoorMes的`+Z`安装面外方向；
- 高模主资产ID和SHA-256；
- 可选中模、低模各自的ID和SHA-256。

共享层通过“右轴 = 上轴 × 朝向轴”生成右手坐标基。Three先应用单位/坐标校准，再测量资产边界，最后按型号声明的真实毫米宽、高、深拟合；因此供应商模型的Z-up/Y-up差异不会散落到各个构件渲染函数里。LOD只替换展示网格，不能改变声明尺寸、枢轴、碰撞或BOM。

目录发布采用追加式历史：设计员提交`in-review`草稿，只有`catalog-approver`或`administrator`可以发布；每次发布生成新的目录版本，并输出主资产及所有LOD的留存清单。历史订单按“目录项ID + 精确版本”解析，禁止自动回退到最新版。兼容导入的旧数据若只有LOD ID而没有对应哈希，可继续降级预览，但必须补齐哈希后才能发布。

## 5. 渲染与选择规则

- Three材质由共享`AppearanceResolver`创建和缓存；场景构建器不再硬编码框灰色、五金橙色或墙体颜色表。
- 框、扇、飞梃等具有内外面的构件必须按观察面应用外侧/内侧外观，侧边使用显式edge外观或可解释回退。
- SVG优先使用快照的基础颜色、透明度和可读纹理标识；不能因2D不支持完整PBR而丢失型号或选中身份。
- 五金模型必须挂在已有`mountOwnerPanelId`运动宿主和规范安装锚点下；更换形状不得改变开合算法、连接ID或工艺坐标。
- 选中辅助色通过临时覆盖/轮廓实现，不修改材质快照。
- 整窗产品、安装墙体和包边/衬板必须使用不同的稳定选择ID。整窗选框只计算框、扇、玻璃、梃和五金，不得把墙体或包边包络算入产品尺寸；选中墙体或包边时，属性面板和尺寸只显示该安装对象的数据。
- 包边业务材料选择器只允许在包边外侧、内侧或衬板槽中出现并提交；选择窗框、窗扇或墙体时不得复用该控件，避免石材包套误改墙体或型材外观。

## 7. 完成门

- 墙、框、扇、玻璃、飞梃、包边和每类五金均可独立选择材质与颜色。
- 同一窗框支持室内、室外和侧边不同外观，2D/3D方向一致。
- 同一安装位置切换至少三种锁具型号时，形状、实际尺寸、选中、开合宿主和碰撞体同步变化。
- 自定义模型保存、重开和目录升级后仍按原版本、原尺寸和原锚点重现。
- 纯外观变化不误改BOM；影响SKU/表面处理/加工模板的选择必须使BOM失效并重算。
- PC、手机和平板得到相同领域快照和BOM；移动端LOD变化不能改变几何尺寸、碰撞或制造结果。
- 缺失或损坏资产可降级显示并产生诊断，不得静默换成另一物资型号。
- 日常设计流程不得要求输入UV、哈希、轴向或枢轴；选择业务型号后必须自动得到同版本的渲染、模型与生产映射。
- 高级目录维护修改纯展示参数时不得使BOM过期；修改被批准的物资/工艺映射时必须使BOM进入`stale`并要求重算。
