# 首个共享核心纵向切片实施记录

版本：0.1.0  
日期：2026-09-17  
状态：通过

## 1. 本次目标

在迁移原型界面前，用最小可执行能力验证以下架构约束：

1. PC和移动端是独立布局壳。
2. 两个壳使用同一设计文档和应用会话。
3. 两端输入最终生成同一种领域命令。
4. SVG与Three.js从同一模型生成并保留稳定对象ID。
5. 壳层不能直接依赖领域、几何、算料和渲染实现。

## 2. 已实现能力

- `DesignDocument`不可变快照。
- `WindowUnit`矩形窗根对象和稳定 `DesignObjectId`。
- `window.create-rectangular`与`window.resize`命令。
- `DesignSession`执行、撤销、重做和订阅。
- 共享SVG渲染，输出 `data-object-id`。
- Three.js框、玻璃场景构建及 `userData.objectId`。
- PC三栏验证壳。
- 手机/平板全屏画布与底部操作区验证壳。
- PC文本输入和移动数值输入适配器。
- 壳层依赖边界测试及跨壳命令一致性测试。

## 4. 真实浏览器验证

1. 在PC壳创建1200×1500矩形窗，对象数由0变为1。
2. PC壳撤销后对象数变为0。
3. PC壳重做后对象数恢复为1。
4. 将视口切换到390×844，系统进入移动壳，对象数仍为1。
5. 在移动壳创建第二个窗体，对象数变为2。

结论：切换壳层不会重建设计会话，PC与移动确实复用同一模型、命令和SVG渲染器。

## 5. 边界说明

当前矩形窗只包含最小框和玻璃表达，是验证架构的临时切片，不是正式原型界面迁移成果。后续必须由原型夹具逐步替换为完整框段、区域、拓扑、开启、材料、制造特征和BOM语义。

## 6. 下一步
