# 自定义模型回读与Three运行时注册进度

版本：0.10.16  
日期：2026-09-18  
状态：功能链与自动验证完成；实际模型外观由用户人工验收

## 本轮解决的问题

此前文件选择、预检和本地落盘已经完成，但上传网关只能查询描述，中央3D工作区也没有运行时资产注册表的装配入口。因此设计虽然保存了模型ID和SHA-256，Three仍显示参数化包络降级体。

## 已实现

- `ManagedGltfAssetGateway`增加按“资产ID + 预期SHA-256”读取原始字节的方法。
- IndexedDB/内存网关直接复用存储端口；HTTP网关先核对描述，再读取原始字节，并在浏览器再次校验长度和SHA-256。
- Vite本地接口增加`GET /api/visual-assets/{assetId}/content?contentHash=...`，只返回精确版本且不暴露磁盘路径。
- 共享工作区从设计快照发现GLB/glTF主资产及LOD，安全解析后注册进Three运行时资产表，加载完成自动重建场景。
- 桌面壳选择高清；移动壳只选择低清优先的一个版本，缺低清时依次使用中清、高清。
- 读取、哈希或解析失败时，Three保留原有参数化/包络降级体，工具栏显示错误，不让整个画布崩溃。
- 工作区销毁时释放运行时模型原型的几何、材质和纹理。

## 验证

- 18个测试文件、159项测试通过。
- 实际从本地HTTP内容端点回读`TEST-LOCAL-BOX-BASIC-20260918`：描述1664字节、下载1664字节，SHA-256完全一致。
- TypeScript严格检查、生产构建和七组冻结BOM夹具通过。
- GLTFLoader继续独立动态分包；主包仍有既有的500kB以上性能提醒。

## 当前边界

- 上传并提交模型后，同一设计会自动切换为真实3D模型；切换桌面/移动壳时也会从本地目录重新读取相应LOD。
- 0.10.20已增加正式设计本地自动保存/严格恢复；整页刷新会恢复此前资产ID、哈希与型号引用，再由本页描述的运行时链读取模型字节。
- 下一步继续精确`hardwareId`单件型号编辑，以及枢轴、安装轴和实际尺寸的可视设置。
