### 首个正式制造规则

正式引擎不直接从SVG或Three.js拼接BOM，而是依次生成：

1. 4个 `ProfileCutFeature` 框料切割特征。
2. 1个 `GlassPanelFeature` 玻璃板特征。
3. 1个 `SealPathFeature` 胶条路径特征。
4. 2个 `ProfileCutFeature` 横、竖压条切割特征。

每个特征包含：

- 设计对象ID。
- 来源构件ID。
- 规则ID。
- 规则版本。
- 材料、尺寸、角度和数量。

第二组规则已把正式布局扩展为多行多列固定玻璃网格，并增加隐式贯通横、竖梃提取。第三组规则加入共享几何拓扑、局部/连续梃长度、闭合矩形分区与T形连接：有效分区生成独立玻璃、胶条和压条；无效悬空分区保留原型的未分玻璃行为，并作为高风险审计项记录。第四组规则加入单扇内开内倒。第五组扩展到双扇飞梃：同一OpeningAssembly驱动P1/P2位置、主动/从动顺序、2D/3D、飞梃和BOM。第六组建立双扇固定中梃审计修正规则：中梃属于外框、左右扇独立启闭、锁座安装在中梃，避免复制原型“画面有中梃但BOM漏料”的缺陷。

### 首个开启制造特征

1200×1500、AL70、右内开内倒样本在外框之后依次生成：

1. 四个 `ProfileCutFeature` 扇料，净长分别为1060、1060、1360、1360mm。
2. 一个 `HardwareDemandFeature` 执手套装：`HW-BS-01`，1 set。
3. 一个 `HardwareDemandFeature` 传动器/铰链：`HW-HJ-70`，2 pcs。
4. 一个980×1280mm `GlassPanelFeature`，再派生4520mm胶条路径及横竖压条。

正式规则没有执行目录表达式，也不在五金缺失时退回第一条目录记录；`height>1800?3:2` 通过有限词汇解析，未知引用直接终止计算。

### 扇框五金连接与工艺保护

同一开启几何现进一步派生扇侧合页片、框侧合页片、执手、锁点和锁座。每对合页及每组锁点/锁座都有稳定连接ID和互相引用的配对ID；2D、3D和工艺提取共用毫米坐标。1200×1500样本生成9个安装位和9个加工要求，但不增加MBOM行：

- 2个扇侧合页片与2个框侧合页片。
- 1个执手安装位。
- 2个锁点与2个框侧锁座。
- 9个对应的钻孔/开槽模板要求。

原型目录没有供应商孔径、孔距、槽深和模板版本，因此这些加工要求状态为 `template-required`，并产生 `HARDWARE_MACHINING_TEMPLATE_REQUIRED` 阻断诊断。目录补齐版本化 `machiningTemplateId` 后，同一工艺特征转为 `ready`，生产确认恢复；材料数量和渲染结构均不改变。

### 双扇飞梃切片

1600×1500、AL70、右主动扇双扇飞梃样本保持原型聚合BOM，同时在正式几何与工艺中保留面板身份：

1. P1为左侧左铰从动扇、操作序号1；P2为右侧右铰主动扇、操作序号0，操作顺序为P2→P1。
2. 四条扇料按730×1360mm单扇尺寸计算，每条数量2；飞梃 `AL70-Z01` 长1360mm、数量1并归属P1从动扇。
3. 五金为2套执手、4件传动器/铰链；共享几何产生18个可视安装成员，工艺层产生18个安装位和18个加工要求。
4. 玻璃为650×1280mm、数量2；胶条7.7m，横竖压条各4件。
5. 兼容MBOM继续使用 `cell.1.1.*` 与原型逐字段对账，面板安装位使用 `cell.1.1.panel.P1/P2.*` 并回链聚合物料特征。

原型未定义双扇交汇边锁座宿主和供应商孔槽模板，因此本切片可人工审阅、可BOM对账但继续禁止生产确认。固定中梃不再套用本段飞梃顺序，而使用后述独立正式规则。

### 可调飞梃与异宽双扇

原型飞梃只由单元宽度二等分，没有独立位置字段。正式模型在不改变默认冻结夹具的前提下增加宿主相对位置：

1. 桌面与移动交互壳可直接拖动飞梃，松手只提交一次共享命令并形成一步撤销。
2. 左侧内径可通过尺寸标注精确输入；左右内径按单元内口到飞梃中心计算，左右外径按窗外边到飞梃中心计算。
3. 1600×1500样本输入620mm后，内径为620/840mm、外径为690/910mm，2D和3D显示同一异宽主动/从动扇。
4. 默认等宽继续输出原型15条聚合MBOM；移动后按P1/P2生成23项异宽制造特征/MBOM，玻璃分别为540×1280mm和760×1280mm，飞梃仍为1360mm×1。
5. 飞梃比例保留9位小数，620/1460回算误差低于微米，避免尺寸与下料计算积累可见偏差。

### 术语、飞梃身份、画布与生产追溯修订

本轮根据人工评审补齐四项正式化要求：

1. 业务属性和工艺说明统一使用“主动扇/从动扇”，P1/P2保持稳定面板ID；内部`primary/secondary`只作兼容枚举，不再把面板称为“主窗/从窗”。0.10.75起产品2D图不再绘制这些角色文字。
2. 飞梃从宿主单元ID中分离，2D、3D和对象树统一使用 `${cellId}:flying-mullion`；3D将梃体前移并增加同身份深色密封面，避免与从动扇交汇边重合后不可见。
3. 桌面网格不再由右侧长属性栏拉伸中央画布，2D内容改为顶部排布并把渲染安全边距由88收紧到64；移动端仍保持全屏画布居中。
4. 正式计算新增 `ProductionMaterialInstance`。型材、玻璃、五金按聚合数量展开为逐件计划生产号，胶条按批编号；每条记录同时保存物资编码、来源设计对象、制造特征ID和来源组件。正式签发、条码及批次冻结继续由BOM-010完成。

### 双扇交汇边锁座宿主修正

人工截图复核发现，0.5.3虽然已让飞梃可见并具备独立ID，但双扇锁座仍沿用单扇默认值 `mountTarget=frame`，所以两扇全开后有黑色锁座悬浮在洞口中央。本轮把连接规则改为两层身份：

1. `panelId`保留锁点/锁座连接来源，`mountTarget`记录实际加工工作件，`mountOwnerPanelId`记录3D运动父级。
2. 主动扇的2个锁座以P1从动扇飞梃为工作件并随P1运动；从动扇的2个原型兼容参考锁座以P2对向扇为工作件并随P2运动。
3. Three.js改为先创建全部面板组，再进行第二遍五金挂载，解决P1规则需要挂到后创建P2组的顺序问题。
4. SVG输出相同工作件/宿主元数据，制造安装与加工特征继续读取同一几何；双扇中不存在任何 `keeper + frame` 组合。
5. 该参考映射消除了错误悬浮，但不会假装已经取得真实供应商规则；从动扇天地插销/传动、孔槽模板和装配顺序仍受生产确认阻断。

### 从动扇真实锁闭语义修订

业务评审进一步确认，飞梃归属从动扇是正确的，但0.5.4为消除悬浮而采用的“从动扇锁点→对向主动扇”只是一项过渡宿主，不能作为正式安装设计。0.5.5在保持旧聚合BOM数量和18个可视五金成员可比的前提下，将从动扇四个连接成员重构为真实角色：

1. P1从动扇不再生成普通侧边锁点和对向扇锁座，改为1个安装在飞梃上的从动扇操作杆。
2. 操作杆驱动上、下2个天地插销；插销以飞梃为工作件并随P1从动扇运动，边语义分别为 `top`、`bottom`。
3. 每个天地插销通过稳定 `connectionId` 配对1个外框锁座；锁座分别固定在外框上框、下框，不随任一窗扇运动。
4. P2主动扇仍保留2个交汇边锁点，配对锁座安装在P1飞梃上；先开P2、再开P1的操作顺序保持不变。
5. SVG、Three.js、对象树摘要和工艺特征读取同一组角色、边、物理工作件与运动宿主。真实页面复核为2个天地插销、2个外框锁座、1个从动扇操作杆，不存在 `opposing-sash` 宿主，控制台无错误或警告。
6. 当前长度、行程和孔槽仍是参考位置；供应商模板缺失时继续输出 `HARDWARE_MACHINING_TEMPLATE_REQUIRED`，不能据此直接加工。

### 双扇固定中梃审计修正规则

原型的固定中梃画面和BOM彼此矛盾，无法做逐字段双跑。0.6.0因此保留审计差异并建立独立正式基线：

1. 固定中梃使用独立对象ID `${cellId}:fixed-mullion` 和来源 `cell.1.1.fixedMullion`，始终留在外框静止组，不跟随任一扇转动。
2. 两个面板角色均为 `independent`，没有主动/从动开启顺序；P1左铰、P2右铰，各有执手、两组合页和两组锁点。
3. 1600×1500、AL70等宽样本中，内口1460mm先扣除70mm中梃，左右扇净宽各695mm；中梃净长1360mm，以 `DW-FIXED-MULLION-001` 生成1件 `AL70-Z01`、两端90°切割。
4. 左右扇共4个锁座的物理工作件均为 `fixed-mullion`，3D父级保持静止；不存在飞梃、从动扇操作杆或天地插销。
5. 中梃中心可复用共享拖动/尺寸命令调整；扇料、玻璃、2D、3D及BOM统一扣除中梃占宽。输入620mm中心位置时左右净内径为585/805mm。
6. 旧v2文件缺失正确固定中梃物料，兼容导入仍阻断并要求用户确认采用修正规则，避免无提示改变历史订单。

## 4. 当前限制

- 正式领域目前完整计算矩形固定玻璃规则网格、隐式贯通横竖梃、局部/连续梃、闭合T形分区、单扇、双扇飞梃及双扇固定中梃内开内倒。
- v2项目、订单、材料目录仍保留在兼容快照中，尚未全部进入正式领域聚合。
- 其余13类开启、其他组合扇、纱窗/辅件、异形、工程节点、组合窗和包套尚未进入新引擎；旧v2固定中梃导入仍需用户确认审计修正规则。
- 悬空未闭合局部梃在原型中会计算型材但不拆分玻璃；正式兼容结果相同，并已禁止生产确认。
- 首个规则沿用原型24mm固定玻璃扣减与毛长算法；规则业务合理性后续单独审计。
- 原型五金目录没有供应商孔槽模板，也没有从动扇天地插销杆长、行程和加工尺寸；正式参考模型已建立操作杆、上下插销、外框锁座、配对及运动宿主，但在供应商模板补齐前不能生产确认。
