# 2D拖动抓手与关联尺寸交互

日期：2026-09-20  
对应版本：DoorMes 0.10.32  
任务：UI-2D-002、UI-2D-004、UI-2D-007  
状态：共享功能完成，等待用户人工检查鼠标与触控手感

## 1. 交互规则

本轮把“能否拖、拖什么、尺寸属于谁”落实为稳定规则：

1. 只有领域命令支持位置调整的贯通梃、拓扑梃和固定/飞梃交汇构件显示右上角拖动抓手；
2. 抓手与整根构件本体都能启动同一种拖动，继续使用6px阈值和一次松手一次命令；
3. 框、扇、玻璃和五金受拓扑、连接与安装约束，当前不伪装成可任意移动对象；
4. 所有工程尺寸文字均有透明扩展命中区，避免必须精确点中细小字形；
5. 单击尺寸选择其所属窗体、格区或交汇构件，双击打开对应数值编辑器；
6. 双击普通格区仍打开PC属性区或移动属性抽屉，可编辑构件类型、扇型组合、开启方向和五金套系。
7. 普通窗体、玻璃、窗扇和尺寸按住超过6px后平移2D视图；它不会改变窗体尺寸、BOM或尚未定义的项目布置坐标。
8. 平移一旦激活，整个按压序列持续更新顶层SVG变换；不会因最初命中对象而只移动一帧。

## 2. 关联尺寸算法

固定中梃/飞梃的左内径、右内径、左外径和右外径共享同一个`dimension-group-id`和交汇构件稳定ID，同时保留独立`measurement-role`。提交时按角色反算同一条交汇中心线：

- 左内径：输入值加固定中梃半面宽（飞梃为0）；
- 右内径：格区宽减输入值，再减固定中梃半面宽；
- 左外径：输入值减格区左起点；
- 右外径：整窗宽减输入值，再减格区左起点。

最终只调用既有`window.opening-move-meeting-mullion`命令，领域层继续负责最小扇宽钳制、撤销、2D/3D重算和BOM失效传播，不从SVG文字反向修改数据。

普通格区宽高按两类情况处理：

- 单列/单行：内尺寸加两侧框面宽，形成新的整窗外尺寸；
- 多列/多行：根据点击格区的起/止边反算相邻贯通分割位置，再调用既有分割移动命令。

## 3. 实现边界

- SVG渲染器只输出稳定对象ID、尺寸组、测量角色、格区轴/边和抓手所有者，不监听DOM事件；
- UI适配器把抓手ID回解到真实构件，继续复用已有拖动预览与命令；
- PC和移动使用同一SVG、同一命中解析、同一尺寸换算和同一领域命令；
- 尺寸输入使用`step="any"`，避免非整数既有尺寸再次触发浏览器“请输入有效值”。

## 5. 人工检查建议

1. 轻点梃本体或抓手均只选中；拖过阈值后才移动，松手只产生一次修改；
2. 分别点击飞梃/固定中梃的左内、右内、左外、右外文字，应始终高亮同一交汇构件；
3. 分别双击四个数值并修改，另一侧关联尺寸、2D、3D和BOM状态应同步；
4. 双击普通格区宽高，单格应改变整窗外尺寸，多格应移动相邻分割；
5. 点击格区并双击，应进入同一构件属性设置；
6. 在移动端重复上述操作，确认抓手足够易点且不会触发画布平移。
7. 从双扇玻璃或窗扇内部按住拖动，应能平移视图；轻点仍只选择，双击仍打开属性。
