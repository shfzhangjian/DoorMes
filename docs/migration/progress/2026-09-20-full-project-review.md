# DoorMes迁移全局复盘与下一阶段执行计划

> 后续范围与顺序已在0.10.37定义为门店/工厂/开发三模式共享核心，并补齐不可变版本、跨模式变更数据流及MS-00至MS-09里程碑；当前仍以工厂闭环为优先。以[目标交付物与里程碑](../deliverables-and-milestones.md)、[三模式工作空间与变更流](../workspace-modes.md)、[门窗工厂设计制造范围与实施顺序](./2026-09-20-factory-manufacturing-scope.md)和`docs/migration/todo.md`为准。

日期：2026-09-20  
对应版本：DoorMes 0.10.29  
状态：R1已完成，当前实施R2

## 1. 总体判断

当前项目已经越过“原型代码搬运”阶段，形成了可以继续扩展的共享核心，不需要推倒重来。PC和移动端保持两套交互布局，但共用设计对象、命令、几何、运动、2D/3D投影、BOM和工艺算法，这一架构方向继续保持。

项目尚未达到“原型全部功能迁移完成”。目前完成度集中在基础框架、已有窗型纵向切片、共享运动、材质/模型和本地数据链；普通/复合推拉、折叠、完整填充、异形、工程节点、多窗组合、业务目录界面、BOM生命周期和全量多端验收仍待开发。

## 2. 已形成的稳定基础

### 2.1 架构与数据

- TypeScript/Vite工作区和19个职责明确的共享/业务/基础设施包已经建立；
- 设计文档、稳定对象ID、命令、撤销/重做和变更集已有正式边界；
- PC与移动布局壳不复制领域、几何或BOM算法；
- 正式快照支持本地自动保存、刷新恢复和项目文件导入/导出；
- 旧原型数据通过阻断式迁移进入正式模型，无法承载的字段不会静默丢失。

### 2.2 2D、3D与联动

- 共享SVG已经覆盖矩形框、规则格、局部/拓扑梃、单扇、两类双扇和上悬窗；
- Three.js实际视口、相机、OrbitControls、拾取、选择联动和资源释放已接入；
- 2D、3D和对象树共用稳定对象身份，具体五金也可逐件选择；
- 总宽高、格区、梃内外径、框/扇/墙深和开启角等标记已有共享数据来源；
- 墙体、窗洞、框位、包边和衬板读取同一Installation毫米模型。

### 2.3 开启运动

- 设计配置与临时预览状态已经分离，播放或拖动角度不会修改设计revision、撤销历史或BOM；
- 平开、内倒和上悬使用共享姿态、角度、轨迹、包络和连接布局；
- 双扇飞梃具有主动/从动顺序，固定中梃左右扇可独立启闭；
- 2D立面、俯视和3D消费同一实际角度；平开参考上限90°，内倒保持独立小角度上限；
- 开启路径会检查墙体、洞口和包边碰撞，并能阻止不可制造配置。

### 2.4 材质、五金和模型资产

- 墙、框、扇、中梃、飞梃、玻璃、包边和五金已有版本化外观快照；
- PBR、纹理、UV和内/外/侧面材质由共享解析器驱动；
- UV支持0.001..1000任意倍率，并可在绑定纹理前独立保存；
- 五金支持参数化形状或真实GLB/glTF、真实毫米尺寸、LOD、安装轴和枢轴；
- 型号可按角色默认，也可覆盖到稳定`hardwareId`单件；
- 模型文件支持预检、哈希、本地持久化、刷新回读和PC/移动LOD选择。

### 2.5 BOM与工艺

- 已有EBOM、MBOM、汇总BOM、下料需求和制造特征基础；
- 固定/拓扑、内开内倒、双扇飞梃、双扇固定中梃和上悬窗已有规则与追溯；
- 型材、玻璃、五金和连续胶条可生成计划生产身份；
- 五金安装位、工作件、运动宿主和加工模板缺失诊断可追溯；
- 目录批准的型材表面映射可生成处理工艺；普通颜色、PBR和纹理不会冒充生产编码；
- 确定性制造输入指纹支持`not-calculated/current/stale`状态，并区分纯展示和生产变更。

## 4. 更新后的开发顺序

### R1：统一2D画布交互（已完成）

对应`UI-2D-007`。

1. 在共享交互层定义命中结果和`select/drag/open-properties/context-menu/pan`意图；
2. 以移动阈值区分单击与拖动，不再让DOM监听器各自猜测；
3. 拖动手柄、尺寸、业务对象、画布空白按固定优先级解析；
4. PC双击聚焦/打开属性栏，移动端使用明确等价操作打开全屏属性抽屉；
5. 现有梃拖动、尺寸双击、右键和长按迁入同一分派器；
6. 增加无DOM纯函数测试和双端命令一致测试。

0.10.28已交付无DOM命中/意图解析器、6px移动阈值、拖后点击抑制、通用对象双击属性、右键/长按共享分派，以及PC属性栏/移动属性抽屉呈现。推拉轨道和多活动扇可直接复用该输入边界。

### R2：生产映射和业务目录核心（当前）

对应`APPEAR-004`、`BOM-009`、`CAT-001`。

1. 定义统一业务目录项、精确版本、适用系列/构件和不可变选择快照；玻璃首个实现已完成；
2. 玻璃规格/SKU与玻璃外观映射已完成，包含共享命令、BOM stale和项目恢复；
3. 补包边/衬板材料与表面处理映射；
4. 补五金业务型号到物资/加工模板/模型资产映射；
5. 完成BOM结果入口、持久快照和过期/重算展示；
6. 证明纯显示变化保持BOM current，生产映射变化变为stale。

### R3：目录功能界面分层

先`CAT-003`，后`CAT-002`。

1. 把当前PBR、UV、哈希、模型轴向/枢轴和生产映射编辑能力迁入独立技术目录维护工作区；
2. 建立设计人员选型入口，只展示业务名称、编码、规格、系列、适用范围和预览；
3. 两个入口读写同一目录模型，设计选择只提交目录项及版本化快照；
4. PC与移动使用不同布局但相同查询、校验和命令；
5. 本阶段完成本地功能，账号、权限、审批和正式发布不参与。

### R4：普通推拉完整纵向切片

对应`OPEN-001`。

1. 2–6扇、1–5活动扇、2–4轨及稳定面板/轨道ID；
2. 左收、右收和双向收拢的共享线性运动策略；
3. 选择、多选、独立拖动、顺序控制和碰撞包络；
4. PC/移动绘制和属性入口；
5. 2D立面、俯视轨迹、3D中间姿态和真实材质/五金；
6. EBOM、MBOM、下料、工艺、生产身份和原型逐字段双跑。

### R5及以后

1. 安装编辑器、现场安装工序和工程节点在`OPEN-003`前关闭，但不阻塞基础推拉；
2. 提升/平行/PSK → 入墙/转角/上下提拉 → 折叠/纱窗；
3. 填充、异形、标记、工程节点、多窗组合；
4. BOM确认/冻结/变更版本及全量PC/移动验收；
5. 最后实施账号、权限、审批、操作审计和生产部署。

## 5. 验收与工作边界

- 自动验证负责类型、算法、命令、快照、BOM、跨壳一致性和生产构建；
- 用户继续负责真实鼠标/触控手感和最终视觉人工确认；
- 人工验收发现的缺陷立即登记并修复，但不会让尚未反馈的视觉门禁阻塞独立功能开发；
- 每个新构件必须同时交付领域模型、命令/意图、2D、3D、PC、移动、BOM、工艺、测试和迁移说明；
- 不为移动端复制核心，不从Three Mesh反算生产尺寸，不让预览状态进入BOM。
