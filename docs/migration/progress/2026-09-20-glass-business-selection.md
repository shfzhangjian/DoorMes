# 玻璃业务目录不可变选型链

日期：2026-09-20  
对应版本：DoorMes 0.10.29  
任务：CAT-001、APPEAR-004、BOM-009  
状态：玻璃子项完成；包边/衬板和五金目录映射继续

## 1. 修复的业务断点

旧设计只保存`defaultGlassTypeId`，正式算料仍在每次计算时查询实时制造目录；玻璃颜色、透明度和PBR外观则独立保存在VisualConfiguration。两条数据链没有精确目录版本和原子绑定，可能产生以下问题：

- 目录升级、改厚度或删除旧项后，历史订单重新计算发生漂移或失败；
- 设计画面显示一种玻璃，BOM却按另一项物资编码或厚度算料；
- 项目文件只能证明一个字符串ID，不能证明设计当时确认的名称、规格、适用系列和版本。

## 2. 新的不可变快照

新增`GlassCatalogSelectionSnapshot`，一次冻结：

- 目录项ID与精确版本；
- `catalog-approved`生产状态；
- 面向设计人员的业务名称和规格；
- 实际玻璃厚度；
- 适用的产品系列；
- BOM使用的物资编码；
- 2D/3D使用的完整版本化玻璃外观。

该快照属于设计数据，不保存实时目录对象或界面状态。目录未来发布新版本时，历史设计仍读取原快照，不自动追新。

## 3. 共享命令与职责分离

`window.update-glass-catalog-selection`在一次可撤销命令中完成三件事：

1. 保存精确业务选型快照；
2. 同步兼容字段`defaultGlassTypeId`；
3. 把快照内的玻璃外观投影到VisualConfiguration。

领域层统一验证目录Schema、批准状态、文本、0–200mm厚度、玻璃材质族和当前型材系列适用性。PC与移动未来只负责选择同一目录项，不得分别改PBR或物资编码。

## 4. 渲染、BOM和历史恢复

- SVG/Three继续读取VisualConfiguration，因此选择命令完成后自然显示同一快照的颜色、透明度和PBR；
- 正式计算优先读取不可变玻璃快照中的物资编码、名称、厚度、目录项和版本；
- 没有新快照的旧设计继续按`defaultGlassTypeId`查询兼容目录，冻结原型结果不变；
- 生产特征保存目录项/版本/规格追溯，MBOM仍使用明确物资编码；
- 玻璃选型进入确定性制造输入指纹，变更后BOM从`current`变为`stale`，撤销恢复`current`；
- 本地自动保存和项目文件导入可恢复完整快照及对应渲染外观；
- 回归已证明：即使计算时实时目录不再返回该玻璃，历史设计仍能按冻结快照生成正确BOM。
