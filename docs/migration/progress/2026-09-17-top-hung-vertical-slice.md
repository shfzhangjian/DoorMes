# 上悬窗纵向切片实施记录

版本：0.7.0  
日期：2026-09-17  
状态：共享模型、2D、3D、兼容BOM、参考工艺及PC/移动验收已完成

## 1. 目标与业务语义

本切片把原型的单扇上悬窗完整迁入正式共享核心。上悬窗不是“左铰平开窗换一个名称”，其窗扇与窗框沿顶部水平边连接，窗扇底边向室外或室内偏转；PC和移动端只提供不同交互壳，领域模型、几何、渲染和算料保持同一份实现。

正式模型采用以下明确语义：

- 开启类型为 `top_hung`，只允许单扇。
- 铰接边为 `hingeEdge: top`。
- `top_out`表示底边向室外偏转，`top_in`表示底边向室内偏转。
- 两组摩擦铰链/风撑沿顶部形成扇侧与框侧配对安装位，执手位于扇底边。
- 原型通用构造器中的 `hingeSide: left`只是不参与上悬运动的旧算料占位字段，不进入正式领域模型。

## 2. 已实现范围

### 2.1 共享领域与命令

- 新增类型化 `TopHungOpeningAssembly`、单扇面板和上悬窗单元。
- `SetWindowCellOpeningCommand`支持 `top_hung`、`top_out`和`top_in`，并进入现有撤销/重做链路。
- v2兼容导入校验单扇和方向，迁移时把旧侧铰占位转换为真实顶部铰接语义。

### 2.2 共享几何、2D与3D

- 几何解析器输出顶部铰接边、窗扇净尺寸、两组顶部连接及底部执手坐标。
- SVG使用标准上悬三角符号，内/外开标签、五金、选择和对象树共用稳定对象ID。
- Three.js将窗扇运动组原点设在顶部中心，绕水平轴旋转；顶部保持连接，窗扇底边按内/外开方向移动。
- 桌面与390×844移动壳均复用相同SVG和Three场景投影，不复制业务算法。

### 2.3 BOM与工艺

- 冻结 `top-hung` 原型输入与BOM输出，旧引擎重放和正式兼容结果逐字段一致。
- 兼容结果包含14条MBOM、10条采购汇总和10条下料需求。
- 正式制造层输出5个物理安装成员对应的5项安装与5项加工模板要求：两组顶部扇/框连接和一个底部执手。
- 旧引擎需要的无意义侧边占位只在兼容适配器内构造；正式BOM/工艺规则使用顶部铰接边。

## 3. 验证结果

- TypeScript严格类型检查通过。
- 11个测试文件、68项测试全部通过。
- 七组冻结原型夹具实时重放通过，其中上悬窗的EBOM、MBOM、采购汇总和下料需求与原型一致。
- 生产构建通过；高危依赖审计为0项漏洞。
- PC真实页面检查上悬外开/内开切换、2D符号、顶部五金、底部执手和3D顶部铰接运动。
- 390×844真实页面检查相同模型、属性抽屉、2D适配和3D运动；浏览器控制台无警告或错误。

## 4. 审计边界

原型目录没有说明摩擦铰链与风撑的具体供应商结构，也没有锁闭件、撑臂展开尺寸、孔距、槽深和加工模板。正式实现因此只把原型可证明的采购数量、参考安装关系和开合运动迁入，不虚构生产参数；计算继续产生 `HARDWARE_MACHINING_TEMPLATE_REQUIRED` 阻断，在真实目录补齐前不得确认生产。

生产构建主脚本约660.68kB，仍触发500kB体积提示。该问题已由 `AUD-PERF-001`/`MOB-008`跟踪，不影响本切片功能验收，但必须在完整移动端发布前完成Three.js按需加载和质量分级。
