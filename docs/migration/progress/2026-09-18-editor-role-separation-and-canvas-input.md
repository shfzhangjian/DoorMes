# 编辑器职责分层、UV校验与2D交互核实

日期：2026-09-18  
对应版本：DoorMes 0.10.26  
状态：两个即时缺陷已修复；统一交互意图和业务目录界面已纳入前置计划

## 1. 人工测试问题结论

### 1.1 UV横向/纵向重复无法输入

这是前端原生数字控件约束错误，不是用户输入错误。

原约束为`min=0.001`、`step=0.1`。HTML会从最小值开始计算合法步进，因此只接受`0.001 + n × 0.1`，常用的`0.5`、`1`、`2`反而都被浏览器判定为步进不匹配。领域模型本来允许有限正数，二者语义不一致。

0.10.25统一改为：

- 最小值`0.001`；
- 最大值`1000`；
- 原生步进`any`；
- 保存时仍由共享领域归一化验证有限正数。

横向和纵向重复共用同一约束常量，测试覆盖`0.001`、`0.5`、`1`、`2`、`2.25`和`1000`。

人工复测随后发现第二层问题：提交器曾把`uvScale`错误地写在“存在纹理集ID”条件内。未选纹理时，合法的`0.5 × 0.5`虽然通过表单校验，却没有进入快照，重绘自然恢复为`1 × 1`。0.10.26已改为始终保存合法UV倍率；没有纹理时它暂不产生画面变化，后续绑定纹理后直接生效。界面增加了这一语义提示，并用0.5持久化和非法边界用例守门。

### 1.2 2D拖动时选中文字

这是画布交互缺陷。此前只有进入梃拖动或画布平移状态后才设置`user-select:none`，浏览器可能在状态确定前先启动SVG文字选择。

0.10.25在两个层面阻止该行为：

1. 2D SVG交互面永久禁止原生文字选择；
2. 左键`pointerdown`在命中分派前阻止浏览器默认文字拖动。

表单和画布外普通文本不受影响。真实鼠标/触控手感仍按约定由用户人工验收，不用浏览器自动操作代替。

## 2. 现有交互能力与缺口

用户提出的事件模型是正确方向：先命中元素，再根据目标、移动距离和输入设备决定选择、移动、属性或画布导航。

当前已经存在：

- 对象和尺寸命中；
- 单击对象选择；
- 固定中梃、飞梃、拓扑梃拖动；
- 空白处平移；
- 尺寸双击编辑；
- PC右键和移动长按上下文操作。

当前缺口是这些规则仍分散在多个DOM监听器，且“通用对象双击打开详情”尚未形成共享意图。新增`UI-2D-007`，在普通推拉`OPEN-001`之前收口：

1. 命中优先级：拖动手柄 → 尺寸 → 业务对象 → 画布空白；
2. 以移动阈值区分点击与拖动，避免按下即误移动；
3. 单击发送`select`；
4. 拖动发送构件专用`drag`并最终提交共享命令；
5. 双击发送`open-properties`，PC聚焦属性栏，移动打开全屏属性抽屉；
6. 右键/长按发送统一`context-menu`；
7. 空白拖动发送`pan`，不触发对象选择。

这样后续推拉扇、轨道、标记和工程节点只注册可命中对象及可用意图，不需要重写整套鼠标/触控判断。

## 3. 业务选型与技术维护结论

现有领域与渲染架构已经区分物资编码、外观快照、五金型号和模型资产，也已把显示`finishCode`与目录批准的生产映射分离。但原计划只写了“共享外观编辑器”，没有明确把最终用户入口拆开；当前屏幕因此把业务型号和技术渲染字段混在一起。这是功能规划缺口。

正式功能调整为两套入口：

| 功能 | 设计业务选型 | 技术目录维护 |
| --- | --- | --- |
| 面向对象 | 门窗设计人员 | 产品、技术或开发维护人员 |
| 主要输入 | 系列、名称、物资/型号编码、规格、适用范围、预览 | PBR、UV、纹理哈希、GLB/LOD、轴向、枢轴、真实尺寸、物资和工艺映射 |
| 输出 | 版本化业务目录项选择及不可变设计快照 | 新的版本化目录映射 |
| BOM语义 | 选择已批准业务型号后按快照计算 | 纯展示变化不影响BOM；物资/工艺映射变化使BOM过期 |

新增任务：

- `CAT-002`：设计人员业务选型界面；
- `CAT-003`：技术目录及渲染/模型/生产映射维护界面。

当前三步PBR/UV/模型编辑器保留为迁移期高级工具，并已增加用途提示；后续迁入CAT-003。CAT-002只复用目录查询、选择命令和不可变快照，不复制底层渲染编辑器。
