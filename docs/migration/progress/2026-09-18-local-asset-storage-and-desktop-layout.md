# 本地模型目录与桌面滚动边界进度

版本：0.10.14  
日期：2026-09-18  
状态：实现与自动门禁完成；浏览器人工视觉验收由用户执行

## 本轮目标

1. PC/移动共享导入器在开发环境把GLB/glTF真实写入可检查的项目目录，而不是只存浏览器IndexedDB。
2. 保持已经固化的授权、哈希、格式/外链/复杂度预检、不可换绑和证据协议。
3. 修复对象树及属性编辑器把桌面画板撑高、产生错误页面滚动条的问题。

## 已实现

- 新增Node专用`FileSystemVisualAssetBlobStore`，按内容SHA-256保存对象字节，资产ID和留存owner经哈希后生成安全文件名。
- 新增Vite开发API：POST申请五分钟grant、PUT上传原始字节、GET查询不可变描述；浏览器不提交actor ID。
- 根目录`.env`已指定`E:/doorMES_v1/DoorMes/runtime-data/visual-assets`，目录在首次成功上传时自动创建。
- 相同内容跨资产ID只保存一个对象；相同资产ID不能换绑其他哈希；描述和留存清单使用临时文件加原子重命名。
- 桌面壳改为单视口两行网格，中心画布不再继承侧栏内容高度。
- 左右侧栏各自纵向滚动；对象树最多占34dvh且不超过360px，拥有独立滚动区和滚动链隔离。
- `runtime-data/`已忽略，避免把本机供应商模型误提交到源码仓库。

## 人工验收入口

- 启动：在`E:\doorMES_v1\DoorMes`执行`npm run dev`；修改`.env`后需要重启。
- 成功样例：`E:\doorMES_v1\DoorMes\test-assets\gltf-import\01-box-basic.glb`等01至04文件。
- 失败样例：同目录05外部URI和06非法JSON文件，必须报错且不能留下资产描述。
- 上传落盘：`E:\doorMES_v1\DoorMes\runtime-data\visual-assets`。
- 布局：右侧对象树内部可滚；右栏属性/材质整体可滚；中央2D/3D不应被右栏撑高，浏览器页面不应出现由右栏造成的纵向滚动。

## 后续边界

- 本地Vite身份是内部开发占位，不建设登录入口，也不参与当前功能验收。
- 正式对象存储、持久grant仓、目录数据库、账号、权限、审计与审批已经移入功能完成后的GOV阶段，不再属于ASSET-003当前关闭条件。
- 本轮不进行浏览器自动操作；最终视觉、鼠标滚轮和工人上传手感由用户人工确认。
