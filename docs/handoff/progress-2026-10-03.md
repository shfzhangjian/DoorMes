# 业务场景与进度交接

核验日期：2026-10-03。本文是当前状态摘要；早期计划和测试日志保留历史上下文，不覆盖本文注明的未完成项。

## 目标与边界

目标是服务门窗工厂的销售、设计研发、工艺、采购、生产和审核岗位。以前端真实操作驱动后端模型和通讯，完成需求、设计、设计 BOM、可行性确认、定稿、生产引用及变更追溯。产品模拟参考此前约定的中窗产品资料，不把公开产品外观当作供应商正式制造参数。

最高优先级是设计账号能完成“新建 → 绘图 → 保存 → 重开 → 修改 → 查看历史”。在此基础上接通标准复用、定制订单和受控变更。包装、运输等外围业务不抢占绘图和设计业务主线。

## 必须延续的界面与绘图约束

- 新建、明细、历史、变更及 BOM 等用弹出视图，绘图用全屏弹窗；不在列表页面内嵌展开编辑区。
- 表格填满父容器，分页固定底部；操作列固定右侧并提供下拉菜单。少量行不能让横向滚动条上浮到行下。
- 2D 工程线稿关注尺寸、编号、开启示意；材质图可单独切换。3D 关注真实材质、开启与空间仿真。保留已有 2D 开窗效果，不擅自改成另一种表示法。
- 室内外标记位于空白区，同视图多窗共享；立面和俯视标记对齐。避免窗名、主从窗、墙厚、安装说明等自动文字充满图面；以后人工文字标签独立维护。
- 尺寸按选择范围显示、可编辑者可点击修改，内部挺间尺寸不能丢失；尺寸关闭时不遗留尺寸文字。编号与尺寸布局要防重叠，可保留人工调整。
- 内部稳定 ID 仅供程序识别。人工短编号由系统初始化、可修改并校验唯一；型号、备注、业务编号分别存储。重编号不应破坏引用或差异匹配。
- 工厂图的图形与组成件表分页面。表格只列设计组成件与参数、编号、备注；不掺生产状态、工序或冻结说明。图纸编号和业务版本必须明确。
- 元件是否输出尺寸、是否列入表格独立控制；未来任意元素的装配图、制造参数和备件关联保留为后续特性。
- 参考墙、包边与实际窗构件分开。多窗转角连接必须以精确几何和规则处理，不能靠视觉覆盖冒充加工精度。
